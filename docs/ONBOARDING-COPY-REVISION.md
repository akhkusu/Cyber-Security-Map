# 主メール・複数メールの登録と言葉の見直し

更新日: 2026-11-14。利用者の追加フィードバックによる必須変更です。実装・検証・公開の終了を分けて記録します。最終的な3観点の独立レビューは、全実装と動作確認が終わった後に実施します。

## 対象とする体験

最初に、他サービスのログインやパスワード再設定に使う一番重要なメールを選びます。サービスを選んだ後、任意のメールアドレス・呼び名と用途を記録します。同じ提供者の複数メール、個人用と仕事・学校用を別の実体IDで扱います。他のメールは必要な人だけが複数サービスを選び、一つずつ追加できます。メインのメールは一覧で明示的に変更でき、他のメールの設定をしても勝手に置き換えません。

初回に候補がない人へ「登録済みのアカウントと同じですか？」とは聞きません。一致する記録が見つかった場合だけ再利用を提案します。名前・同じ提供者・アドレスの別名という推測で統合せず、本人が同じ実際のアカウントと選んだ場合だけ設定記録を共有します。ドットやプラス記号を消すアドレス正規化はしません。同じログインで使う別アドレスを本人が明示した場合は、一つのAccountへ追加し、同じ認証設定を二度要求しません。

メールアドレスは、このアプリでメールを区別する目的で任意入力できます。従来の「アドレスは入力しない」という一律の説明は、この新しい方針に置き換えます。保存は既存のブラウザー内暗号化だけで行い、住所・メールアドレス・呼び名等をAI相談文へ含めません。実際のパスワード、認証コード、復旧コード、QR・秘密鍵を入力させない条件は継続します。任意アドレスは本人確認・メール受信成功・サービス側登録完了の証拠にはしません。

## 必要な文言と導線だけを残す

- 「一つずつ、設定まで。」「まず、メールから。」「ONE STEP AT A TIME」「進むたびに途中保存」など、操作・判断に役立たないコピーを削除する。
- サンプルを試す入口と、暗号化せずにサンプル編集へ入る本番経路を削除する。
- 機種変更の新規入口はSecurity Mapの端末詳細へ置く。主ガイドに買い替えの見出し・新規起動ボタンを出さない。進行中の任意作業の再開は簡潔なリンクで保持する。
- 「選択だけで認証は有効になりません」等の当然の注意書きや内部実装の説明を削除する。
- 操作対象の呼び名・任意アドレス・用途を設定画面の上部へ表示する。後回しの作業にも対象メールを併記し、スマホで再開入口が下方へ埋もれないようにする。
- 手順の進捗バーは、今進めている設定に対して保存済みの完了手順を数える。分岐後の不要な手順を数え続けず、後回しを完了にしない。安全度・保護率の数値として表示しない。
- 公式メニュー名は実際の表記を保ち、本文は自然な日本語にする。「Account」「基盤」「語句」「回転」等は、製品名と何を指すかが伝わる言葉へ直す。

## 登録と進行の契約

`mailboxIdentityV1`は、既存Account上の任意アドレスと呼び名です。`guide.mailAccountsV1`は、対象メールID・主メールID・現在の対象・個別の再開位置・訪問済みの一覧を保持します。追加中のメールはそれぞれ固有の下書きID・提供者・実際のAccountへの参照・残る追加サービスの列を持ち、戻る操作や別メールの編集によって後続サービスを誤消費しません。主メールの変更は保存失敗時に以前の選択へ戻り、キーボードのフォーカスも戻します。既存の暗号化封筒やデータ本体の版を変えず、未知の名前空間は読み書きで保持し、解釈できない既存値を上書きしません。

登録やメイン指定だけではMFA・復旧等のコントロールを完了しません。完了は既存の具体的な操作ガイドと実施記録から判断します。「訪問した」「後回し」「設定済み」は区別します。別メールへ移った後も元の手順へ戻れ、パスワード管理へ進むときは主メールを既定の重要対象へ戻します。仕事・学校用の設定権限の確認は残します。参照中のメールを黙って削除しません。

## 操作の実効性を直す残件

初期の3観点の点検で以下を発見しました。全実装後の最終レビューとは別です。

1. Google・Microsoftの「復旧手段が使えることを確認」「3つ用意」だけの前提を、開く設定・実際の登録・受信・現在状態の確認へ分割する。登録済みなら不要な変更を要求しない。Microsoftの個人用に根拠のない3件必須を設けない。
2. 標準Bitwarden・1Passwordの保存／パスワード変更は、既存項目を先に探し、強く固有な既存パスワードを変更せず使える分岐を用意する。既存項目を二重作成しない。
3. 保存パスワードの実利用と、パスキー等による別方式のログインを区別する。
4. プライベートウインドウを使う作業には、対応するOS・ブラウザーの開き方をアプリ内から案内する。
5. 任意の物理キー入口は、主要操作より先に全画面で出さず、認証方法を選ぶ場面へ整理する。

根拠: [Googleの再設定情報](https://support.google.com/accounts/answer/183723?hl=ja)、[Microsoftの本人確認情報](https://support.microsoft.com/ja-jp/accounts-billing/manage/microsoft-account-security-info-verification-codes)。実装時に現在の公式本文・実メニューと適用条件を再照合する。

## 受け入れ条件

| ID | 条件 |
| --- | --- |
| UX01 | 初回にサンプルや飾りコピーを出さず、記録の暗号化から主メールへ進める |
| UX02 | 主メールのサービス・任意アドレス・呼び名・用途を記録できる |
| UX03 | 同じ提供者の仕事用・個人用・別の個人用を区別できる |
| UX04 | 複数の追加サービスを選び、それぞれのメールを一つずつ登録できる |
| UX05 | 同じ実際のAccountの再利用は既存記録を維持し、推測で統合しない |
| UX06 | 主メールの選択を変更でき、設定対象の切り替えだけでは変更しない |
| UX07 | メールを切り替え、後回しにしても元の手順から再開できる |
| UX08 | 任意アドレスと全進行が既存の暗号化バックアップで往復し、平文やAI相談に出ない |
| UX09 | 登録・用途・主メールの指定だけでセキュリティ設定を完了にしない |
| UX10 | 機種変更の新規入口はMapにあり、主画面に買い替えの見出しを出さない |
| UX11 | 設定の進捗がスマホでも読め、後回しを完了にしない |
| UX12 | 復旧準備で、非技術者が押す項目と受信・登録の結果を判断できる |
| UX13 | 強い既存パスワードを維持し、保存済み項目を二重作成しない |
| UX14 | 保存パスワードの確認を他方式のログイン成功へ読み替えない |
| UX15 | プライベート画面を開くために外部の説明記事を読まなくてよい |
| UX16 | 全実装後に日本語・使いやすさ・個人への実効性を独立レビューし、有用な指摘を実装する |
