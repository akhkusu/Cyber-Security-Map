# 認証アプリを使える状態にするガイド

更新日: 2026-11-14。Google・Microsoft・Bitwardenの資料確認日: 2026-11-13。2FAS: 2026-11-14。これは[製品別の到達仕様](PASSWORDS-AUTHENTICATORS-SPEC.md)の一部を実装した契約です。新しいコードの登録と、機種変更・バックアップからの復元の対応範囲を分けます。

## 実装した範囲

| 製品 | 今回の登録経路 | 保存方法・前提 | 未実装の主な経路 |
| --- | --- | --- | --- |
| Google 認証システム | iOS / Android、別画面のQR・同じスマホの手入力キー | アカウントなし／本人が選んだ個人Google Accountとの同期。実際の同期先の認証・復旧へ接続 | 組織固有条件、全バックアップ方式の復元試験 |
| Microsoft Authenticator | iOS / Android、他サービスのTOTP・個人MicrosoftのQR登録 | 画面ロック、App Lock、既存の登録・バックアップを保持 | 通知・パスワードレス・職場／学校登録、異なるOS、Google One方式。機種変更の同じOSの経路は追加済み |
| Bitwarden Authenticator | iOS / Androidの単独アプリ、QR・手入力キー | 今回の新しいコードを「Save here」で保存。既存の同期コードを変更しない | 常設のバックアップ運用・単独復旧等。機種変更のローカル／保管庫同期は追加済み |
| Ente Auth | 正規4.4.26、iOS / iPadOS 15以降・Android 7以降、QR・手入力 | 既存コード・Accountを保持。端末とアプリロック、手動／自動の暗号化JSON・Accountの追加認証・復旧情報を別に確認。[専用契約](ENTE-AUTH-GUIDE.md) | 変更・再設定・認証解除、Photos / Locker側の別Root、全旧版・全管理環境 |
| 2FAS Auth | iOS / iPadOS 18.6以降、Android 9以降、Auth 6系、QR・手入力 | 端末ロックとPIN、実際の同期先、暗号化.2fasファイル。詳細は[専用契約](TWOFAS-AUTH-GUIDE.md) | 旧端末なしの専用復旧、HOTP・Steam・Watch・拡張、管理環境・全旧版 |

既にMFAが有効な人に、認証アプリを再登録させません。新しい認証コードの追加が必要な段階でだけ、製品と実際の保存端末を質問します。既存の準備済みアプリを選んだ場合、端末や導入を重ねて質問しません。

Microsoft・Bitwardenの `codeStorage: local` は、今回追加するコードの経路を示します。既存アプリの全コードがローカルのみ、同期もバックアップもない、という記録ではありません。機種変更では、既存の混在した保存方式を別途確認する必要があります。

## 一つずつ進む操作

1. 使っているアプリ、または新しく導入する製品を選ぶ。
2. 実際にコードを使うスマホを選ぶ。旧データでOSが不明なら、同じ端末IDのOSだけを確認する。
3. 必要な場合だけ保存方法・実際の同期先Accountを選ぶ。同名の個人用・仕事用を一つにしない。
4. 正規配布元のアプリを開く。導入済みなら、そのまま使い、既存コードは残す。
5. 同じ端末の画面ロックを確認する。既に確認した記録があれば再利用する。MicrosoftはApp Lockを別に確認する。
6. アプリの実際の保存方法を確認する。選択しただけで確認済みにはしない。
7. QRが別画面か、同じスマホで手入力キーが表示されているかを選ぶ。
8. 選んだアプリの追加操作を行う。正規サービスが発行したキーは認証アプリだけに入力する。
9. 正規サービスの登録画面で、現在のコードを受け付けたことを確認する。
10. サービス側で有効になった状態・復旧手段を確認し、次の必要な対策へ進む。

Googleの同期先がまだ保護されていない場合、本人が同期を確認した後に、その実際のGoogle AccountのMFA・復旧へ案内します。主メールのIDは変更しません。既存の同じAccountの確認は共有し、同期を独立した予備手段とは扱いません。

登録用QRしかなく、同じスマホで読み取れない場合は、未完了のまま分岐します。サービスに手入力キーがあると推測せず、確認済みのProton・mail.com・GMXの項目だけを案内します。キーを外部のQR読取りサイトへ送る構成はありません。

## 既存コードを守る条件

- Googleの初回「アカウントなしで使用」と、同期中の既存アプリをアカウントなしへ変更する操作を区別する。後者を案内に合わせるために行わせない。
- Googleの別の同期Account・ローカルプロフィールは、異なるアプリ実体として保持し、確認済み状態をコピーしない。
- Bitwarden Password Managerの統合TOTPと、単独Authenticatorを区別する。保管庫自身を開く唯一のコードを、同じ保管庫へ同期させない。
- Microsoftの一定時間で変わるコードと、通知承認・パスワードレス・仕事の再登録は別の経路にする。終了済みのパスワード自動入力を案内しない。
- 正しい登録を確認する前に、既存の認証方法・コード・バックアップを削除させない。

## 記録・Security Map

物理Device、端末上のアプリ／保存プロフィール、値を持たないTOTP Credential、認証対象Accountを別のIDで記録します。秘密キー・現在のコード・復旧コードを保存する入力欄はありません。

| 確認した操作 | 記録すること | その確認だけでは証明しないこと |
| --- | --- | --- |
| 製品・端末を選ぶ | 計画上の参照 | アプリの導入、MFAの有効化、利用可能な関係 |
| 正しいアプリを開く | その端末への導入・利用の確認 | 対象サービスへの登録 |
| Googleの実際の同期先を確認する | そのアプリと正規Accountの同期関係 | 独立したバックアップ・紛失後の復元 |
| アプリに項目を追加する | そのAccountの追加操作の記録 | サービスにコードが受け付けられたこと |
| 同じ登録操作のサービス側確認を終える | 値を持たないコードと保存先・対象Account、登録時の受け付け | 通常ログイン、新端末ログイン、バックアップからの復元 |

スキャンとサービス側確認は、Account・アプリIDと一回の登録操作の識別子で対応させます。古い確認を、新しく読み取ったコードの受け付けに流用しません。後日「有効」と確認しただけで、コードの受け付け日時を更新しません。

利用観測の文脈は `enrollment` です。Mapは「コード登録の記録あり」と表示し、通常のログイン試験とは分けます。失った端末の想定は、その記録の実際の参照に適用します。再登録した場合、古いコードのコピー・バックアップの利用観測は未確認に戻します。履歴やバックアップ実体は消しません。どの認証方法が失効したかを自動検査したとは扱いません。

スキャンまたはサービス側確認を取り消すと、派生するアプリの確認・関係を取り下げ、観測を未確認に戻します。他の記録から参照される利用経路は残します。外部サービスのMFAを無効にしたことにはしません。

同じApple・Googleの実際のAccountを選び直した組込み管理は、既存の保管庫を再利用します。確認・関係・履歴を持たない仮のIDのみ、元のIDと未知項目を残して既存の実体へ対応付けます。別Accountや別ローカル保存先を、製品名だけでまとめません。

## 任意の機種変更との境界

[機種変更の仕様](DEVICE-CHANGE-LIFECYCLE-SPEC.md)に従い、通常の設定ガイドとは別に進行します。機種変更にはGoogleに加え、Microsoftの同じOSのコード復元、Bitwardenの端末内／保管庫同期・混在の確認を追加しました。適用条件、対応する直接転送、既存の新端末データを残す分岐は[認証アプリの機種変更契約](AUTHENTICATOR-PHONE-MOVE.md)を参照してください。未対応の引き継ぎが残る場合、旧端末の消去へ進みません。

移行では、アプリの存在だけでなく、全コードの保存方式、同期／ファイル／OSバックアップ、実際の復元先、再登録が必要な対象、各サービスでの新端末のコード受け付けを確認します。仕事用の名前が復元されたことと、その認証が使えることを区別します。

## 例外・AI相談

画面違い・キーがない・同じスマホのQR・別製品等はアプリ内の分岐から始めます。解決しない場合だけ、製品名・認証アプリ側のOS・サービスの作業・現在の操作・想定表示・選んだ困りごと・公式根拠を手動コピーできます。秘密情報、Accountや端末の呼び名、自由入力の回答は含めません。自動送信はしません。

AIには最新の公式情報の確認、一度に一つの質問・操作、確認できない場合の明示を指示します。画像を添付する場合は、個人情報・コード・復旧情報を隠すよう表示します。

## 2FAS Authの追加

[2FASの専用契約](TWOFAS-AUTH-GUIDE.md)でTF01〜24、配布ソースの版、OS・日英文言・暗号化書き出し・同じOSの同期と4方向のファイル移行を管理します。2FAS Passとは分けます。PINとファイル用・同期用の秘密は別の実体で、実際の値を保存しません。同じ物理アプリで確認した同期設定やファイル用の語句は再利用でき、見直す時だけ別の確認を始めます。過去の操作へ戻っただけなら、同じ設定をやり直すことなく保存した確認で進めます。

## Ente Authの追加

[EN01〜36の専用契約](ENTE-AUTH-GUIDE.md)で、版・OS・保存方法・既存Account・共有範囲・秘密の違いを管理します。サービス登録後に不足するバックアップと実際のEnte Accountの保護へ戻り、選択・導入だけでサービスのMFAを完了にしません。Accountパスワード、24語のRecovery key、手動／自動のファイル用語句、端末／アプリロック、Security Mapの保存用語句を混同させません。主ガイド・補助・機種変更の戻り先を区別します。専用ガイドの一部を実装したもので、全EN条件の完了ではありません。
