# 認証アプリの機種変更ガイド

更新日: 2026-11-14。既存3製品の資料確認: 2026-11-13、2FAS: 2026-11-14。[機種変更の到達仕様](DEVICE-CHANGE-LIFECYCLE-SPEC.md)と[認証アプリの登録ガイド](AUTHENTICATOR-GUIDE.md)を補完します。この文書は今回実装した経路の契約です。候補にある全製品・全復旧方式の実装完了を示しません。

## 今回の対応

| アプリ・方式 | 対応する機種変更 | 条件と残る範囲 |
| --- | --- | --- |
| Bitwarden Authenticator・端末内 | iPhone同士、Android同士 | JSONの書き出し、本人の新端末への直接転送、取込み、実利用、一時ファイルの整理 |
| 同・端末内の異なるOS | 対応PixelとiPhone、または本人が保護して転送済みのJSON | 直接相互運用はPixel 9以降（9aを除く）の確認済み範囲。その他機種の直接転送は未対応として保持 |
| 同・保管庫同期 | iOS、Android 12以降 | 正しいPassword Managerと単独Authenticator、実際の各Bitwarden Account。複数の同期元・端末内との混在を扱う |
| Microsoft Authenticator・コード | iPhone→iPhone、Android→Android | 同じOS。既存の新端末データを残し、対応するバックアップから復元後にコードを試す |
| 同・iOSの新規復元 | 旧アプリ6.8.33以降 | iCloud Drive・キーチェーン・Authenticatorの対象指定・バックアップ。新端末でのリセットや再インストールへ誘導しない |
| 同・Androidの新規復元 | 個人Microsoft Accountを使うCloud Backupの現行表示 | Google One方式・別の表示は版別の未完了分岐。2027年1月の予定だけで新版と判定しない |
| Ente Auth・暗号化JSON | 4方向、確認済みの直接転送または本人が保護して転送済みのファイル | 既存コード・Accountを保持。恒久コピー・一時ファイル・解除用語句を区別し、各Accountで新しいコードを使う。[専用契約](ENTE-AUTH-GUIDE.md) |
| Ente Auth・同期／復元 | 同じ実際のAccountの同期、またはMapから旧端末の操作を要しない暗号化ファイル復元 | 同期・既存端末の全組み合わせの試験、機種変更全体の紛失後の経路は追加対象。保管だけを利用確認にしない |
| 2FAS Auth・暗号化ファイル | iPhone同士、Android同士、対応するiPhone・PixelのOS間、または本人が保護して転送済みの.2fas | パスワード付き書き出し、別の恒久コピー、取込み、対象ごとのコード利用、一時コピーの整理 |
| 2FAS Auth・クラウド同期 | iPhone同士／Android同士 | 同じ実際のApple／Google Account、設定済みなら現在の同期用パスワード。新端末の既存コードを維持 |
| すでに新端末へ移っているコード | Microsoft・Bitwarden・2FAS | 元のアプリと照合してサービスで試す。復元・書き出しを繰り返さず、復元元を確認したとも推測しない |
| Google 認証システム | 既存の同期／ローカル移行 | iOS・Androidのメニュー差を維持。登録済みの複数プロフィールはまとめて完了せず、専用の未完了分岐を追加 |

Microsoftの仕事用・通知・パスワードレスは、一定時間で変わるコードと別です。混在する場合はコードの確認を進めつつ、残る登録を未完了にします。異なるOSのMicrosoft復元、旧アプリを操作できないバックアップ単独の復旧、残る認証アプリは追加対象です。

## 入口・質問の順序

通常ガイドの途中位置・全回答は保持します。機種変更の途中位置・回答・確認記録は、同じ暗号化データ内の独立した作業に保存します。

1. 旧端末の登録済みアプリを確認する。確認したアプリを、一般質問の「ほかには使っていない」だけで消さない。
2. 必要なら追加の製品を一つずつ選ぶ。導入・移行が完了した記録にはしない。
3. 旧アプリを開いて、実際のグループ・登録を確認する。
4. 新端末の既存アプリ実体を使うか、新しい実体を準備する。別の物理端末の確認をコピーしない。
5. 端末内／同期／混在や、コード／仕事用等を確認する。以前追加した一つのコードの保存方法から、アプリ全体を推測しない。
6. 新端末の状態を確認する。すでに必要項目があるなら、不要な復元へ進まない。
7. 今回必要な転送・復元だけを行う。
8. 対象Accountごとに、新アプリのコードを実際の正規ログインで使う。
9. 全項目の対応を確認する。未登録・未対応のAccountは未完了として残す。
10. 一時ファイルを整理し、残る機種変更の確認へ進む。

現在のアプリを識別できる製品名を、質問画面にも表示します。一般のアプリ選択、バックアップ方式、実際の同期Accountは別の意味として管理します。

## Bitwarden Authenticator

Password Manager統合のTOTPと単独アプリを区別します。端末内のJSONと、各保管庫から同期されるコードは別の復元元です。書き出しに同期コードが含まれるとは案内しません。[公式の書き出し・取込み](https://bitwarden.com/help/authenticator-import-export/)

端末内では、旧アプリのJSONを本人の新端末へ移し、単独アプリで取り込みます。iPhone同士はAirDrop、Android同士はQuick Share、対応するPixelとiPhoneは直接の相互運用を案内します。対象端末・受信を確認し、他人や外部の読取りサービスへ秘密ファイルを渡しません。異なるOSで既に本人が保護して移したファイルがある場合は、その実際のファイルから続けられます。

Googleの相互運用資料には送信・受信の機種説明に差があります。今回の直接転送は、両方で明示されるPixel 9以降（9a除く）に限定します。その他メーカー・モデルや、サーバー上へ一時保存するQR転送を、この経路に無条件で混ぜません。[Quick Share公式説明](https://support.google.com/android/answer/9286773?hl=en)、[AirDrop公式説明](https://support.apple.com/en-ie/119857)

JSONは読取り可能な秘密キーのファイルとして扱います。本アプリへファイル・内容・コードを取り込む機能はありません。移行用の一時ファイルを、暗号化された長期バックアップと表示しません。すべてのコードの実利用と独立した復旧を確認してから、新旧端末の一時コピー・受信先・最近削除した項目を整理します。コード自体や独立して保護したバックアップは残します。

同期では、旧アプリのグループに対応する実際のBitwarden Accountを一つずつ選びます。既存のIDを使い、別Accountを同じ製品名だけで統合しません。新端末のPassword Managerで正しいAccount・保管庫を使い、単独Authenticatorにそのグループが表示されることを確認します。複数の同期Accountがある場合も、それぞれ確認します。[同期の公式説明](https://bitwarden.com/help/totp-sync/)

端末内と複数保管庫が混在するときは、コードごとの実際のグループも聞きます。一つのローカルコードの利用に、無関係な全保管庫Accountが同時に必要だと推測しません。保管庫自身を開く唯一のコードを、同じ保管庫へ移す操作は追加していません。

## Microsoft Authenticator

新規復元は同じOS間で、実際の復旧Account・現在の設定画面を確認して行います。名前だけ・追加ログイン待ちの項目を、使えるコードと扱いません。すでに新端末で必要コードが表示されている場合、確認のために再インストールやサインアウトを要求しません。[公式復元説明](https://support.microsoft.com/en-us/authenticator/restore-account-credentials-from-microsoft-authenticator)

iOSの経路では、旧アプリの適用版、実際のApple Account、iCloudの必要な設定を確認します。旧バックアップを消したり、新端末の空の情報で上書きしたりして画面を合わせません。新端末全体の正常なバックアップ確認は、コードの移行後にも行います。

Androidでは、表示が個人Microsoft Accountを使うCloud Backupかを確認します。Google Oneへ変わった表示や不明な版は、その版の未完了作業として保持します。変更予定の日付だけで新しい経路の動作確認済みと扱いません。[公式バックアップ説明](https://support.microsoft.com/en-us/authenticator/back-up-your-accounts-in-microsoft-authenticator)

仕事用・通知・パスワードレスが混在する場合、一般TOTPの復元とまとめて完了させません。新しい登録が使える前に、旧登録を削除する操作も行いません。

## 共通の記録とSecurity Map

物理端末、端末上のアプリ、本人が選んだ実際のAccount、値を持たないコード、一時的な書き出しデータを別に記録します。選択しただけでは、導入・同期・利用の関係を確認済みにしません。

| 確認 | 記録すること |
| --- | --- |
| 正しいアプリを開く | その物理端末上のアプリの確認 |
| 新しく転送・復元した項目を照合する | 確認した移行元の関係。すでに表示済みの確認だけから、復元元を追加しない |
| Bitwardenの実際の同期グループを確認する | アプリと各Accountの同期関係 |
| Microsoftのバックアップ設定を確認する | 復元に必要と確認した実際の基盤Account。バックアップの完成や復元試験の成功とは別 |
| 新端末のコードで正規ログインを完了する | 正しいAccountへの追加認証とログインを別の観測として記録 |
| 一時JSONを書き出す | 秘密を含まないファイルの所在種別・出典情報。中身は保存しない |
| 一時コピーを整理する | 実ファイルの削除済みという本人の記録。記録を取り消しても、ファイルを復活させない |

新端末のコード利用は `new-device` の文脈です。通常利用・全端末紛失後の復元試験へ変換しません。利用に必要な参照は新アプリ・新端末・対象Account・確認したコード等です。移行元の履歴があるという理由だけで、旧端末が消えると新コードも使えなくなるとは判定しません。

コード確認でログインも完了したAccountへ、同じ一般ログインを再要求しません。保管庫を読めたことは別の確認として残し、必要な場合だけ追加します。同期のAccountを、メール・別Account・別の保存先と混同しません。

各操作は、必要な先行確認を参照します。前提の確認を訂正すると、それに依存して作った利用観測・関係・コントロールも未確認へ戻します。直接の前提だけでなく、書き出し→転送→取込み→コード利用の連鎖も対象です。外部のMFA設定を無効にしたとは表示しません。参照される観測・経路と未知項目は残します。

新端末・保存方式・同期元を選び直したとき、異なる条件の完了を流用しません。コードの数が多い場合も、登録済みAccountの数に合わせて続けます。小さい固定件数に達しただけで、残りを確認済みにしたり、最初の同じ項目だけを繰り返させたりしません。

## 出典の確認方法

- Bitwarden・Microsoft・AirDrop・Quick Shareの記載は公式本文を照合しました。
- iCloudキーチェーン・アプリ対象指定もApple公式本文を照合しました。
- iCloud DriveのiPhone向け個別手順は、直接取得の429応答と、公式検索に表示された本文を区別して記録します。アプリの出典欄にも確認方法を表示します。[iPhoneの公式手順](https://support.apple.com/guide/iphone/set-up-icloud-drive-iphbbcf8827d/ios)
- 第三者の設定画面画像・秘密のサンプルは再利用していません。添付画面は、このアプリを架空の名前で表示したものです。

公式資料での確認、アプリ内の経路テスト、実機の転送・認証試験は別です。全OS・全機種・実アカウントで外部操作まで照合したとは表示しません。

## 実装と残る作業

`src/phoneAuthenticators.ts` が製品別の質問・手順・適用条件、`src/phoneAuthenticatorRecords.ts` が実体の作成・観測・取り消しを担当します。`src/phoneEngine.ts` は独立した進行と先行確認を検査し、`src/PhoneGuide.tsx` が同じUIで表示します。外部サービス固有の操作をUIへ散らしません。

引き続き、Googleの複数プロフィールの専用移行、Microsoftの異なるOS・仕事用等・Google Oneへの変更、未対応機種の直接ファイル転送、旧アプリを操作できない復元、残る認証アプリ、全実体の編集・アーカイブ、実機照合を追加します。[実装状況](IMPLEMENTATION-STATUS.md)に検証結果と対応範囲を反映します。


## 2FASの追加契約

[専用契約TF01〜24](TWOFAS-AUTH-GUIDE.md)を参照します。コピー元・別の恒久保存分・新端末への一時転送分は別IDの物理ファイルとして記録し、同じ内容のグループへ結びます。元ファイルや旧スマホの後日の消去で、現在の独立したコピーまで消去済みにしません。復元元は過去の由来であり、現在のローカルコード生成に毎回必要な依存とは区別します。

新端末のコードが実際に受け付けられた記録は追加認証だけに限定し、パスワードを含む一般ログインまで成功にしません。初期化・登録の失効、別の新端末・アプリ実体への変更、前提の記録の取り消しでは古い確認を流用しません。旧端末が使えない専用復旧や他製品からの取込みは未完了です。
