# 2FAS Authの登録・バックアップ・機種変更

資料確認日: 2026-11-14。2FAS Passは別製品。この追加契約は全体196条件、製品別仕様、機種変更36シナリオ、AR01〜16、DP01〜20を置き換えない。実装・試験の結果は末尾と実装状況で別に示す。

個人所有で解除できるiPhone / iPad、Androidの2FAS Authを対象とする。現行配布のiOS / iPadOS 18.6以降、Android 9以降、2FAS Auth 6系の確認済みの画面を案内する。OS・表示が異なる、管理されている、PINを失った、旧端末がない場合は、通常の直接移行を完了にしない。

## 通常のコード登録

サービス側で新しい認証コードが必要なときだけ2FASを選ぶ。導入済みのMFAやコードを説明のために作り直さない。実際のスマホとアプリを選び、適用OS・版、正規アプリ、画面ロック、2FASのPINの順に一つずつ確認する。既存のPINを維持でき、忘れた場合に再インストールを先行させない。

QRは別の信頼する画面から読み取る。同じスマホなら、正規サービスが手入力用の設定キーを提供している場合だけ手入力へ進む。設定キーやQRをSecurity Map、外部の読取りサイト、AIへ渡さない。追加のパラメーターは、サービスに指定がある場合だけ変更する。

2FASにコードが表示されたこと、サービス側の今回の受け付け、MFAが有効な表示、復旧手段の保管、通常ログインでの利用を区別する。コードの表示だけでサービスの認証設定を完了にしない。設定の最後に必要なバックアップを案内し、すでに設定済みのサービスへ再登録を要求しない。

## PIN・同期用・ファイル用の秘密

端末のロック、2FASのPIN、任意のクラウド同期用パスワード、書き出したファイルのパスワード、Apple / Googleの認証情報、本アプリの保存用フレーズを区別する。実際の値は一切入力させない。

新しくバックアップ用の秘密を用意する場合は、同梱のEFFの7776語から物理サイコロで独立した6語以上を選び、半角ハイフンでつなぐ。空白・日本語が使えると案内しない。配布ソースの最低3文字は製品の受け付け条件であり、安全な推奨値ではない。固定した完成例は使わせない。紙の控えはコードやファイルだけと同じスマホに閉じ込めず、本人が管理できる場所へ保管する。

既存の秘密を維持できる。既存の同期用パスワードを忘れたとき、コードが開ける旧端末から独立した暗号化コピーを確保する前に、同期・PINを解除したり、アプリを消したりしない。未確認のリセットをデータ復旧成功と扱わない。

## バックアップの案内

実際に2FAS Backupを開き、同期の現状を確認する。同期OFFと、同期先をまだ聞いていない状態を分ける。iOSは本人のApple Account、Androidは選択したGoogle Accountを既存の実体へ結び付ける。製品名や同じ呼び名だけでは別Accountをまとめない。別の同期先へ切り替えることを通常の解決策にしない。

必要な場合だけ同期のON、追加パスワードの有無と外部での確保を一つずつ扱う。同じOSの同期だけをOS間の復元として案内しない。同期は、同じ削除も他端末へ伝える仕組みであり、独立した別方式の認証とは数えない。

確認済みの同期先・追加パスワードの設定は同じアプリの後続作業で共有し、一般質問を繰り返さない。変更があれば、現在のファイル作業を残して同期の見直しを別に始める。既存のファイル用の語句も本人が明示して再利用でき、再作成を強制しない。

ファイルは2FAS BackupのExportからパスワード付きで書き出す。暗号化の指定、専用の語句、控え、実際の保存、旧スマホ以外から取り出せる保存先を分ける。保存するだけで復元試験を済ませたとは表示しない。新しいコードの追加や再登録後は、以前のファイルを最新と扱わず、更新が必要な理由を示す。既存の有効な別の確認は保持する。

## 新しいスマホでの利用

機種変更の任意ガイドから、実際の旧アプリと新しい物理端末を引き継ぐ。新端末にあるアプリを再利用でき、選択だけで導入・復元・利用確認をコピーしない。基本ガイドの全回答・途中位置を保持する。

| 状態 | 進め方 |
|---|---|
| 必要なコードがすでに新端末にある | 復元し直さず、ロック・対象のコード・サービスでの受け付けを確認 |
| 同じOSのクラウド同期 | 実際の同じApple / Google Accountと、設定済みなら現在の同期用パスワードを確保。新端末の既存データも残す |
| 同じOSの暗号化ファイル | 既存の新端末コードを残し、本人が取り出せる最新の暗号化ファイルから取り込む |
| iPhone→Android / Android→iPhone | iCloudとDriveの同期を共通復元にせず、パスワード付きファイルで移す |
| 新端末に別の同期先・唯一のコードがある | 同期先変更・初期化を要求せず、ファイルによる追加か未完了へ分岐 |
| 旧端末を使えない・不明な版・HOTP等の未確認の方式 | 正常な直接移行の完了を作らず、必要な別の復旧・調査として残す |

取り込めた表示と、サービスで新端末のコードが受け付けられたことを別に確認する。既存のログインを残し、新しい未ログインの環境で対象ごとに試す。コードの確認を、パスワードを含む全ログインや全端末喪失後の復旧の成功へ広げない。別のコード・通知等で通過した場合は成功にしない。

コピーした同じ秘密は同じ複製グループへ結ぶ。別の方式を新設したという記録にしない。旧端末の初期化後も新端末の実際のコード利用の記録は残し、対象サービスの再登録・初期化・失効後は古いコードの成功を復活させない。

ファイルの元の保存分、別の保存先の恒久コピー、新端末への一時コピーは、同じ内容のグループへ結んだ別の物理実体として記録する。元や一時コピーの削除を、残る恒久コピーや新端末内のコードへ伝えない。保存先・解除情報を失った場合は現在のバックアップと扱わない。復元元の線は過去の由来として表示し、現在の利用の依存と分ける。

移行用の一時コピーは、恒久的なバックアップと分けて整理する。安全に確保した暗号化バックアップを、移行の一時ファイルと混同して一括削除させない。旧端末の売却・譲渡へ進む前に、対象の引き継ぎが未完了なら既存の消去ガードを通さない。

## 記録・互換性・例外

アプリの実体、物理端末、対象Account、値を持たないPIN・復元用情報の種類、クラウドAccount、ファイル、各コピーと実利用を別IDで管理する。モデルrevision11の専用ストアを必要時だけ追加し、旧1〜10の未知項目と既存の封筒・バックアップ・進行を保持する。同名の不明な従来項目を上書きしない。

選択・設定・保管・復元・実利用の記録を分ける。質問の訂正と確認の取り消しを派生する根拠へ反映し、過去の履歴と実際の変更は残す。別の新端末・別Account・別アプリへ完了を流用しない。説明の更新だけで完了記録を消さない。

画面違い・項目がない・権限がない・PIN／解除情報が使えない・別方法で通過した場合は、その場で未完了にできる。内蔵の分岐で解決しない場合だけ、製品・OS・適用版・現在の一操作・期待表示・困りごと・公式根拠を匿名で手動コピーする。AIには最新の公式情報の確認と一度に一問／一操作を指示する。自動送信しない。
