# 手順カタログの更新

`PRODUCT-SPEC.md` が製品全体の要件、`IMPLEMENTATION-STATUS.md` が現在の対応・検証範囲です。

パスワード管理・認証アプリの製品別契約は `PASSWORDS-AUTHENTICATORS-SPEC.md`、Google・Apple・Bitwardenの境界・到達モデル・削除は `MAJOR-PLATFORMS-MODEL-AUDIT.md` を併用します。`SPEC-GAP-REVIEW.md` から不足と受け入れ条件を追跡します。

`DEVICE-CHANGE-LIFECYCLE-SPEC.md` は、通常のガイドと別に必要時だけ起動する機種変更・旧端末の継続利用・譲渡・売却の契約です。主ガイドの途中位置を上書きせず、共通のAccount・認証・バックアップ記録を参照します。

## ファイルの責務

- `src/guideCatalog.ts`: サービス別・端末別の操作、期待表示、日英文言、分岐、公式の操作先、出典・適用範囲・確認日。
- `src/guideEngine.ts`: 安定IDによる途中位置、前提条件、完了・取り消し・後回し、既存記録の引き継ぎ、関係の追加、AI相談文。
- `src/Guide.tsx`: 一つの質問・操作の表示と例外支援。製品固有の設定名を増やすときは、可能な限りカタログへ置きます。
- `src/SecurityMap.tsx`: 同じ作業記録に基づくグラフ、状態の理由、確認した関係、紛失時の影響の可能性。
- `src/models.ts`: v1互換の追加スキーマ。`src/crypto.ts` の保管庫名・暗号化封筒は変えていません。

## 新しい提供者を追加する条件

1. 認証主体を確認します。同じログインで複数サービスを使う場合は、別アカウントを作りません。
2. 公式資料を読み、地域、契約、OS・ブラウザー、個人用・組織用を分けます。
3. メニュー名、QRやコードの登録、復旧の前提、成功条件を確認します。公式文書が曖昧なら、未確認のメニュー名を補いません。
4. 有効化前の復旧・ログイン維持、有効化後の復旧情報保管、既に有効な場合、画面差異、権限不足の経路を作ります。
5. 一つの操作に一つの主ボタンを基本にし、最終確認だけが対象の対策を更新するようにします。
6. 日英両方の文章、出典URL、適用範囲、確認日を設定します。資料確認と実機確認を混同しません。
7. アカウントを選んだだけで完了しないこと、同一アカウントの重複排除、別アカウントへの誤伝播がないことをテストします。
8. スマホ、キーボード、途中再開、例外経路、PagesでE2Eを実行し、対応表を更新します。

## ID・記録の維持

レシピとステップのIDは、タイトルや配列の番号にしません。表示文言だけを変更するときはIDを維持します。操作の意味そのものが変わる場合は、旧IDからの再開先を定義し、過去の完了記録は証拠として残します。

完了した設定は対象IDとコントロールIDで一元管理します。1つのApple Accountのメール・Drive等で設定を共有し、名前が似た別アカウントとは共有しません。新しい説明を配るだけで、既存の`controls`、`actions`、`assessmentAnswers`、旧ワークフローを消しません。

## 出典と画像

出典リンクは実際の操作先とは別です。通常フローはカタログの説明だけで進めます。図解はアプリが作成した操作の順序図で、「実画面ではありません」と表示しています。現時点で、第三者の設定画面を再配布したり、架空のスクリーンショットを生成したりしていません。

実画面画像を追加する場合は、取得元、再利用条件、OS・版、取得日、代替文、個人情報・認証情報のマスク内容を同じ変更に含めてください。権利・実画面の根拠が確認できない画像は採用しません。

## 検証

```sh
docker build --target checks -t cyber-security-map:checks .
docker build --target browser-tests -t cyber-security-map:browser-tests .
docker run --rm --shm-size=1g cyber-security-map:browser-tests
docker run --rm --shm-size=1g cyber-security-map:browser-tests npm run test:pages
```

公式側にログインして設定を変えるテストは、本人が管理するテスト用アカウントで別に実施します。リポジトリのE2Eが通ったことを、その代わりの証明にしません。

## 主要プラットフォームとモデルの変更

- サインイン、追加認証、復号、ローカル解除、セッション、外部権限を一つの`mfa`へ集約しません。レシピが満たす役割と前提を宣言します。
- 同時に必要な条件・代替経路・待機・組織の条件を失う二項関係への変換をしません。紛失時の評価は状況と未確認を保持します。
- 実施の履歴と、失効・紛失後の現況を別に更新します。記録の取り消しで外部の削除を取り消したことにしません。
- 移行前の原本、未知項目、参照、モデル版を検証します。旧コードが新形式を変更保存して捨てることを防ぎます。
- 公式資料が相違する場合は双方の適用条件を記録し、未照合のOS・機能を対応済みにしません。検索抜粋だけの確認と本文・実機照合も区別します。
