# 個人の機種変更・旧端末の継続利用・譲渡と売却

版: 1.4 / 初回調査日: 2026-11-13 / 追加確認日: 2026-11-14

この文書は、通常の基本対策ガイドと別に、必要なときに始める「端末を買い替える」経路の必須仕様です。新しいスマホを買った人が、新端末で必要なことを終え、旧端末を自分の意図に合わせて扱えることを目的にします。企業の機器台帳や退職手続を個人へそのまま当てはめません。

[全体仕様](PRODUCT-SPEC.md)、[製品別仕様](PASSWORDS-AUTHENTICATORS-SPEC.md)、[主要3系統とモデルの再監査](MAJOR-PLATFORMS-MODEL-AUDIT.md)の保存・秘密非収集・本人の確認・一画面一操作の契約を維持します。この文書は到達仕様です。任意ガイドの初期経路を実装しましたが、36シナリオの全分岐に対応したという意味ではありません。実装範囲は末尾と[実装状況](IMPLEMENTATION-STATUS.md)で区別します。

## 1. 通常ガイドとの関係と入口

- 上位メニューは「対策を進める」「Security Map」「設定」の3つを維持する。
- Security Mapの端末詳細に「この端末から買い替える」を置く。
- 「対策を進める」から、任意の作業として「端末を買い替える」「古い端末を手放す」を始められる。
- 初回の基本対策の必須経路に、機種変更の質問を混ぜない。機種変更をしない人へ繰り返し聞かない。
- 主ガイドの途中位置を保持し、この作業を中断・完了したら元の作業へ戻れる。
- 機種変更中も、Account・認証・バックアップの実施記録は共通のデータへ反映する。別コピーの「完了」を増やさない。
- 長いチェックリストを渡して本人に実行順を決めさせず、必要な次の質問か操作を一つずつ表示する。

案内する機器は常に「新しいiPhone」「これまでのAndroid」等、本人が区別できる呼び名を併記します。同じOS・同じ製品名でも別IDです。「この端末」とだけ書き、どちらを操作するか分からなくなる画面を作りません。

| 場面 | 日本語 | 英語 |
| --- | --- | --- |
| 作業を始める | 端末を買い替える | Move to a new phone |
| 旧端末の用途 | この端末も使い続ける | Keep using this phone |
| 予備にする | 予備として残す | Keep it as a backup phone |
| 売却・譲渡 | 手放す準備を進める | Prepare this phone for a new owner |
| ログインの確認後 | ログインできました | I could sign in |
| 新端末の利用確認後 | 新しいスマホで使えました | It works on my new phone |
| 通常ガイドへ戻る | 元の作業へ戻る | Return to my previous task |

作業後の主ボタン一回で、本人の確認を記録して次へ進みます。別画面で同じ「移行済み」を再確認させません。

## 2. 入口で扱う状況

最初に「今、どの段階ですか？」を聞きます。その後の質問は必要なときに出します。

| 状況 | 最初に進めること |
| --- | --- |
| これから買い替える | 旧端末での復旧・バックアップ・移せないものの準備。未購入の端末を実在・設定済みとして記録しない |
| 新しいスマホを手に入れた | 旧端末が使えるか、新端末のOSと設定済みかを確認して開始 |
| すでに新しいスマホを使っている | 新端末の利用確認から入る。既存データを消して最初から設定し直さない |
| 旧端末が壊れた・使えない | 既存バックアップ・別端末・独立復旧から進む。旧端末のQRを要求しない |
| 古い端末だけを手放したい | 重要なデータ・ログインの別の利用場所を確認し、売却・譲渡の経路へ進む |
| もう売却・譲渡してしまった | 遠隔で確認・失効できるものを選ぶ。端末が手元にある手順を続けず、未確認を残す |
| 一時的に貸す・修理に出す | 所有移転とは別の経路。必要な情報の露出・公式の修理手順を扱う |

旧端末の今後は「自分が使い続ける」「予備として保管」「家族等へ譲る」「売る・下取り」「処分」「まだ決めていない」から選べます。移行後に変更できます。未定だからといって新端末の準備を止めず、初期化の提案も出しません。

## 3. 四つのOS間経路と例外

| 移行 | 必須の分岐 |
| --- | --- |
| iPhone→iPhone | Quick Start、iCloudまたは暗号化ローカルバックアップ、旧端末の有無、管理端末、既に新端末を設定済みの場合 |
| Android→Android | 新端末のメーカー・OS・設定段階、ケーブル／無線、バックアップ、Pixel・Samsung等の手順差 |
| iPhone→Android | メーカー・OS・接続方法、iCloudだけのデータ、iMessage等の受信、移らないアプリ・認証情報 |
| Android→iPhone | 現行のApple公式移行方式、設定段階、旧端末の有無、容量、個別アプリの引き継ぎ |

移行ツールが初期設定中だけ利用できる場合は、それを先に知らせます。既に新端末へデータがある場合、再転送のための初期化を自動的に勧めません。上書き・消去の対象と現在の新データのバックアップを確認し、消去せず移す経路か保留を選べます。[P01〜P04]

中古の新端末に前所有者のActivation Lock等が残る場合は、正規の所有者・販売元による解除へ分岐します。ロックの回避や、前所有者のAccount・パスワードを共有する方法を案内しません。組織所有・管理下の端末は、本人の権限を確認します。

## 4. 案内の順序と移行の到達条件

順序は、公式のセットアップ・キャリア・アプリ固有の前提に合わせます。一律に「SIMは必ず最初」「すべてのアプリは自動で移る」と決めません。

### 段階A: 消す前・回線を動かす前の準備

1. どの旧端末からどの新端末へ移すかを本人が確認する。
2. 旧端末を解除できるか、基盤Account・メール・マネージャーへアクセスできるか確認する。
3. 認証・復旧・移行に必要な情報を、旧端末だけに閉じ込めていないか確認する。
4. 現在のバックアップの対象・日時・正常終了・解除に必要なものを確認する。
5. 旧端末で使っている重要なアプリと役割を、既存のMapから確認する。未登録の重要なものがあるかも一度確認する。
6. 使っている人だけ、認証アプリ、メッセージ、決済、交通系、電子ID、Watch等の固有の準備へ進む。
7. 新端末の容量・接続・OS等、選んだ公式移行方式の前提を確認する。
8. ガイドを旧端末で見ている場合は、消去前に新端末または別の利用場所でガイドを続けられる状態にする。

秘密の値のリストをこのアプリへ入力させません。バックアップ解除用の秘密、マスター、復旧コード、eSIMのQR、IDの暗証番号は、本人が公式の製品間で扱います。

### 段階B: 新端末での基礎設定と転送

1. 公式の設定アシスタントを開き、新端末をロックできる状態にする。
2. 本人の正しいApple／Google等のAccountを使い、必要な更新・利用者確認を進める。
3. 選んだ公式経路でデータを転送・復元する。転送中・復元中・アプリの再ダウンロード中を別に扱う。
4. SIM／eSIM・回線の移行を、キャリア・端末の確認済みの順序で行う。
5. 新端末で電話・SMS・通信が使えるか、本人の目的に合う方法で確認する。テスト用の有料通話や送金を必須にしない。
6. 元の端末と既存の復旧経路を残し、次の個別アプリの確認へ進む。

eSIMの移行では、新しい回線が有効になった時点で旧SIMが無効になる方式があります。回線変更の前に、SMSが一時的に使えなくても進められる認証・復旧を確認します。両端末で同じ番号のSMSを同時に受信できると約束しません。[P05]

### 段階C: 新端末で「使える」を確認

以下は、本人が利用しているものだけを一つずつ表示します。

| 対象 | 確認すること | 完了にしない例 |
| --- | --- | --- |
| 主なメール・基盤Account | 新端末で正しいAccountの受信・必要なサインインを利用できる | メールアプリのアイコンがあるだけ |
| マネージャー | 正しいサーバー・Account・保管庫を開き、重要ログインを保存先から利用できる | アプリを再インストールしただけ |
| パスキー | 対象Accountで新端末から使用でき、保存先・同期・旧端末固定の違いを確認 | 鍵の一覧が見えるだけ |
| 認証アプリ | 製品・OSに合う復元・転送・再登録を行い、対象の公式サービスが認証を受け付ける | 同名の項目が表示された、コードが出たというだけ |
| 仕事・学校 | 必要な管理者承認・デバイス登録・再登録を確認 | 個人用の認証復元が済んだだけ |
| 写真・連絡先・ファイル | 本人が残したいデータを新端末や選んだ保存先で確認し、クラウドだけ／端末内の区別も確認 | 転送の完了表示だけ |
| メッセージ | Accountの引き継ぎ、受信、残したい履歴・メディアの範囲を別に確認 | Accountへログインしただけ |
| 決済・交通系・銀行等 | 本人が使う製品の移行・再登録・端末認証の状態を確認 | OSのバックアップ復元だけ |
| 電子ID・電子証明書 | 新端末での登録・利用と、旧端末側で必要な失効等を製品別に確認 | 端末を初期化すれば必ず消えるという想定 |
| Watch・イヤホン等 | 必要なペアリング・認証・データへのアクセスを確認 | 旧端末とのペアリングを残しただけ |
| このアプリの作業記録 | 適切なURL・ブラウザーで暗号化バックアップを復元し、途中位置とMapを確認 | OSの転送でブラウザー内データも必ず移るという想定 |

コードやパスキーの表示だけで、各サービスで使えると判断しません。対象によっては端末登録・生体認証・通知・再承認が必要です。別の認証方式を削除する前に新方式を確認します。

移せないデータは、移せなかったことを明示して残します。本人が説明を理解して「これは移さない」と選ぶことはできますが、「復元できました」という記録には変換しません。履歴の消失やアクセス不能を、一般の「次へ」で黙って了承させません。

### 段階D: 新端末を普段使いにする

1. 新端末のロック・生体認証・必要なOS更新を確認する。
2. 端末に対応する紛失・盗難保護を確認する。
3. 新端末のバックアップの対象・保存先・初回の正常終了・必要な解除情報を確認する。
4. 基盤Account、重要アプリ、予備の認証・復旧が新しい構成でも使えるか確認する。
5. 本人の用途に合わせて、新端末を「主に使うスマホ」として記録する。
6. 旧端末の今後の扱いへ進む。未決定ならここで中断できる。

主に使うスマホが変わっても、すべてのAccountの通知先・認証優先先が自動的に新端末へ変わるとは表示しません。サービスごとの設定を確認した分だけ更新します。

## 5. 旧端末を使い続ける・予備にする

### 5.1 自分が使い続ける

写真用、Wi-Fi用、旅行用、予備のログイン用等、本人の目的を必要な範囲で確認します。所有者が同じだからという理由で初期化・全ログアウトを要求しません。

- 画面ロック、利用するOS・アプリの更新、紛失保護を確認する。
- 回線を移した場合、旧端末でSMSやモバイル通信が使えると誤表示しない。
- 残すAccount・パスキー・認証アプリ・同期・通知の役割を本人が選ぶ。
- 不要な機能だけを、影響を示して個別に整理する。
- 更新提供が終わった端末では、利用目的に応じた限界を説明し、重要な認証を残すかを別に判断する。
- 新旧端末を同じAccountで同期する場合、旧端末での写真・連絡先等の削除が、新端末側にも及ぶことを操作前に示す。[P06]

### 5.2 予備として保管する

「端末が1台増えた」だけで独立した復旧が完成したとはしません。電源を入れ、解除し、必要なログイン・認証が使えること、必要な回線やネットワークへ接続できることを確認します。

同じクラウド・同じ保管庫へ依存する予備、同じ場所で同時に失う予備、ローカル状態が消えると利用できない予備を区別します。保管場所は「自宅とは別」「同じバッグ」等の区分だけを扱い、住所を記録しません。定期確認は本人が選ぶ作業として残し、外部通知や自動実行を追加しません。

旧端末に認証アプリを残す場合も、製品が複数端末・サブ端末の利用に対応するか確認します。新端末をメイン端末として登録したことにより旧端末が使えなくなるアプリを、予備として有効と数えません。LINE等のサブ端末は製品・OS・版ごとの対応を確認します。[P10]

### 5.3 継続利用・予備の一操作ずつの案内

用途の選択は予定の回答です。それだけでは「使える予備」の確認を作りません。新しい作業は次の順で案内します。

| 画面 | 操作する場所・今回の操作 | 次へ進む条件 |
| --- | --- | --- |
| 画面ロック | 旧端末の正規設定でロックを確認し、一度ロックして解除する。強い設定があれば変更不要 | コード・生体認証等による解除を確認 |
| 更新画面 | 旧端末のOSに合うソフトウェア更新を開く | 現在の状態・提供された更新が表示される |
| 更新の適用 | 先に確保した旧端末のバックアップを残して、必要な更新・再起動を行う | 適用が終わり、現在の状態を確認。未対応・不明は保留 |
| 残す用途 | 新端末を使わず、旧端末で実際に残す用途を試す。通信が必要ならWi-Fiも確認 | ログイン用なら正規サービスで実利用。コード表示だけでは不可 |
| 予備の保管 | 予備の場合だけ、ロックした端末を他人が使えず本人が取り出せる場所へ置く | 保管を終えた本人の操作一回で用途の記録と次への移動を行う |

自分で使い続ける場合の主ボタンは「使えました」、予備の保管後は「保管しました」とします。保管場所の住所・解除コード・実際のログイン情報は収集しません。新端末へ移した回線のSMSを旧端末でも受信できるとは表示しません。

- 予備の役割と、独立した復旧経路を分ける。この一般的な用途の確認から、全Accountの利用観測・復旧の線は追加しない。製品別・Account別の観測は個別経路でのみ記録する。
- 同じバッグの紛失、同じクラウドAccountへの依存を説明する。「2台ある」だけで独立と判定しない。保管後も、次に頼る時点の電源・更新・通信・用途の確認を案内する。
- 「まだ決めていない」は保持の意思だけを記録する。元の可用性・用途を変えず、故障端末を利用中へ戻さない。
- 故障・ロック等で操作できない旧端末は、使える予備に確定しない。使用可能になった時点で、可用性の質問から現在の状態を確認する。
- 確認前の後回しや直接の画面遷移では、必要な確認を飛ばして予備の用途を確定できない。前提の取り消しでは派生する用途の確認も撤回する。
- 同じ物理端末に別の任意作業の確認があれば、一方の取り消しで他方を消さない。最後の確認を取り消したときは元の用途・未知項目へ戻す。後で実施された消去・所有移転・紛失の状態を取り消さない。
- 過去のまとめた「旧端末を残す」確認は保持する。新しく分割したロック・更新・Account利用を自動で確認済みにせず、既存利用者へ一律のやり直しも要求しない。用途を変更したときは新しい用途に必要な手順へ進む。

更新画面に新しい更新がないことは、メーカーのサポート継続を証明しません。機種別の提供終了判定と、その端末へ重要な認証を残す判断の専用手順は、引き続き追加対象です。

## 6. 旧端末を譲る・売る・下取り・処分する

### 6.1 手放す前の確認

ガイドは「新端末の移行が完了した」と「旧端末を手放す準備ができた」を別の到達条件にします。

1. 必要なデータ・重要ログイン・認証・回線を、旧端末なしで使えるか確認する。
2. 残すデータのバックアップと、取り出すための解除情報を確認する。
3. Watch等のペアリング、決済・交通系、電子ID、仕事用管理など、旧端末での固有の処理を完了する。
4. 正規所有者として、売却等に必要なAccount・端末保護の解除を行う。Google AccountやApple Accountそのものを削除しない。
5. 物理SIM、取り外せるメモリーカード等を確認し、回線移行後のeSIMの処理を公式手順で選ぶ。
6. 公式の端末初期化を行い、終了と引き渡す状態を確認する。
7. 必要なサービスの端末・登録・セッションを、確認済みの範囲で整理する。
8. 売却・譲渡した事実をMapへ記録し、本人の有効な認証・バックアップ端末として数えない。

新端末で使うのに旧端末の登録解除を先に要求する製品は、公式の影響・復旧・別経路を調査して専用分岐にします。未検証の削除を先にさせて「あとで復旧できる」と保証しません。安全な移行経路を確認できなければ、その製品を保留し、旧端末の消去へ進めません。

### 6.2 OSと製品による違い

Appleの現行の売却・下取り資料では、Parts and Service HistoryのFinish Repair表示の確認も必要です。表示がある場合だけ、修理を完了してから下取りへ進む分岐を設けます。iOS 26以降とiOS 18以前でサインアウト時の選択が異なるため、確認したOSの経路を使います。古い端末の写真や連絡先を手作業で消す片付けには誘導しません。2026-11-14に[公式資料の本文](https://support.apple.com/en-us/109511)を再確認しました。この追加条件の専用操作UIは継続対象です。


- **iPhone**: Apple公式の売却・譲渡手順に沿って、バックアップ、移行、必要なペアリング解除、サインアウト、消去等を分割する。同期中の写真や連絡先を手作業で削除して掃除する経路にしない。[P06]
- **Android**: メーカー・OS・管理区分を確認し、端末からのAccount除去と端末保護・初期化を正規の手順で扱う。購入者へ自分のGoogle Accountや解除情報を渡させない。OEM unlockingや保護回避を一般の売却手順へ入れない。[P07]
- **盗難・紛失**: 売却と別経路。iPhoneのFind My登録を外すとActivation Lockへ影響するため、盗難対応で売却用の解除を勧めない。[主要3系統の再監査A08]
- **家族への譲渡**: 本人のAccountを共用する方法を既定にしない。相手のデータ・年齢・管理条件を尊重し、通常は前所有者の情報を整理した端末を渡す。相手のパスワードをこのアプリで設定・保存しない。
- **処分・故障**: 画面操作ができるか、遠隔処理が届くか、取り外せる媒体・回線があるかを確認する。物理的に消去完了を確認できない場合、その事実を残す。「必ず完全消去できた」と断言しない。

### 6.3 電子証明書等の初期化だけでは済まないもの

Androidスマホ用電子証明書について、デジタル庁は端末初期化とは別の失効・削除手続を案内しています。すでに初期化した場合と、端末が故障・手元にない場合も別の経路があります。[P11]

利用していると答えた場合だけ、機種・製品に合う公式の確認・失効・停止を案内します。Androidの手順をApple Wallet等の別の電子IDへ流用しません。端末内の鍵・チケット・企業の証明書についても、初期化だけでサービス側の登録や権限が消えるとは扱いません。

## 7. アプリ固有の移行

### 7.1 認証・マネージャー

[製品別仕様](PASSWORDS-AUTHENTICATORS-SPEC.md)の同期・ローカル・書き出し・復元・OS間の契約を再利用します。Google Authenticator、Microsoft Authenticator、Apple、Bitwarden等の全利用者へ、同じ移行手順を割り当てません。

Microsoftの仕事・学校の登録は、バックアップから項目名が戻っただけでは再利用できない場合があります。管理者確認と新端末の再登録を別作業にします。[P08]

マネージャーは既存のサーバー・Account・保管庫へ入る経路を優先し、再登録や全パスワードの変更を要求しません。端末固定のパスキー、同期されたパスキー、物理キーへの登録を別に確認します。旧端末の登録を消すのは、新端末での利用と予備を確認した後の別作業です。

### 7.2 メッセージ・決済・ID

- **LINE**: Accountの引き継ぎ、トークの範囲、バックアップ・PIN、同一OS／別OS、旧端末の有無、メイン／サブ端末を分ける。パスキーを用意しただけでAccountと履歴が自動移行するとは説明しない。[製品別契約LM01〜40](LINE-PHONE-MOVE.md)に、現在の必要版・18の一次資料・一操作の画面・例外・切替前の条件を具体化した。仕様段階であり、アプリへの接続は未完了。[P09・P10]
- **Signal**: Direct Transfer、Secure Backups、On-device backupを別の方式として扱う。OS間・旧端末なし・解除情報・含まれる履歴の条件を方式別に確認する。一般的な「SignalはOS間で移せない」という古い断定を使わない。[P12]
- **WhatsApp等**: 使用製品・移行元と先のOS・設定段階に合う個別レシピを登録する。OSのデータ転送で履歴を全て移せたと確定しない。新端末の既存メッセージを失う再インストールは、事前確認なしで行わせない。
- **決済・交通系**: カード・チケットごとの移行・端末紐付けを確認する。Apple Walletの交通系カードのように一度に利用できる端末数の条件があるため、旧新の同時利用を保証しない。[P13]
- **銀行・電子ID等**: 本人が使う提供者の新端末登録・旧端末解除・認証を、公式資料と本人の管理権限に合わせる。テストのための送金・決済・本人確認書類の提出を、このアプリから要求しない。

資料相違も追跡します。Signalの公式概要とトラブル対応資料には、On-device backupの対象OSについて異なる記載を確認しました。レシピでは方式・アプリ版・OSを確認し、未照合の復元経路を対応済みにしません。クロスOSのSecure BackupsとDirect Transferの区別は保持します。[P12]

## 8. このアプリの記録も新端末で続ける

このアプリはブラウザー内保存のため、スマホ本体の引っ越しで途中位置まで必ず移るとは扱いません。

1. どの端末でガイドを続けるかを選ぶ。PCで続ける場合は、不要なアプリデータの移行を要求しない。
2. 移す場合は、元のブラウザーから暗号化バックアップを保存する。
3. 保存用パスフレーズを本人が別に確保する。スマホのPIN、マネージャーのマスターとは別であることを示す。
4. 新端末で同じ公開元の正規のアプリを開く。GitHub PagesのプロジェクトURLも正しく扱う。
5. 既存データがある場合は置換範囲を本人が確認して復元する。無断の上書き・暗黙の統合をしない。
6. 同じ途中位置・Map・作業記録を開けることを確認する。
7. 以降どちらのブラウザーで作業するかを明確にする。二つのコピーが自動同期すると表示しない。
8. 元端末の処理へ戻る。本人が選ぶまで元の暗号化原本を消さない。

古いバックアップは作成時の保存用パスフレーズを必要とします。新端末や新しい保管庫でフレーズを変えただけで、古いファイルも新フレーズで開くようにはなりません。

DockerをPCのlocalhostで起動している場合、スマホのlocalhostは同じサーバーではありません。必要な配布先の説明を分け、機種変更のために自動公開・外部向けポート開放を行いません。利用可能な配布先がなければ、PCでガイドを継続できるようにします。

## 9. 保存モデル・再開・Map

機種変更は独立した`workflowInstanceId`を持ち、主ガイドの途中位置と別に保存します。少なくとも次を表現します。

- 種類: 機種変更、継続利用、予備、売却・譲渡、処分、修理、一時貸与。
- 旧端末ID、新端末ID、操作を表示している端末の役割、本人が選んだ旧端末の今後。
- OS・版・メーカー・旧端末の可用性、新端末が設定済みか。必要なものだけ質問する。
- Account・データ集合・認証情報・回線・アプリごとの移行タスクと必要条件。
- バックアップ、移行、利用確認、復旧、旧端末の整理を別々の到達条件として保持。
- 履歴、途中位置、分岐、後回し、本人が移さないと決めた対象、確認日時、未解決事項。
- 通常ガイドへ戻る位置。別の端末の機種変更と干渉しないインスタンス識別。

個別製品の利用一覧と未解決項目も作業単位で保持します。既存の `special-apps=yes` をLINE利用と推測せず、LINEが終わっても銀行・電子ID等の別項目は完了にしません。新端末の独立した準備と、旧端末を消去・譲渡できる状態を分けます。詳細は[LINEを最初に接続するための製品一覧と戻り先の契約](LINE-PHONE-MOVE.md)を参照してください。

端末は`planned / preparing / in-use / backup / to-be-transferred / transferred / lost / retired`等のライフサイクル状態を持てます。状態名だけで認証の利用可否は決めず、対象ごとの登録・保存先・確認に基づきます。

新端末ができたからといって旧端末の線を全部コピーしません。移行方式と本人の確認によって、移ったもの、複製されたもの、新規登録したもの、残ったもの、無効になったものを区別します。「主に使うスマホ」という役割の変更で、物理端末のIDや過去の履歴を書き換えません。

売却済み・譲渡済みの端末を有効な予備に数えません。継続利用する端末を、古いという理由だけで削除しません。途中で「やはり売らずに残す」へ変更したときも、完了した別Accountの設定を巻き戻しません。

主ガイドとこの作業が同じAccountに影響した場合、完了記録は一度だけ反映します。片方の取り消しで、他方の正しい実施記録や外部設定が取り消されたことにしません。

## 10. 例外・誤操作からの復帰

- 旧端末がない: バックアップ・別の利用可能な端末・復旧の順に、存在する経路だけを提示。
- 新端末の初期設定を済ませた: 消去なしの経路を先に検討し、既存データを守る。
- 回線移行でSMSが来ない: キャリア・番号・回線状態・代替認証を確認し、旧端末の消去を止める。
- コードやパスキーが使えない: Account・保存先・OS条件・登録と復号を確認し、秘密を相談文へ入れない。
- 一部の履歴が移らない: 公式の適用範囲と現在のデータを確認し、残りを未完了として保留。
- 初期化を先にした: 消えた情報が戻ったとは扱わず、製品ごとの復旧・失効手順へ分岐。
- 端末をすでに渡した: 到達する遠隔失効・停止を確認し、未確認の消去を完了にしない。
- 管理者の制限・対応外: 回避を勧めず、依頼する具体的な作業と未完了を残す。
- 案内で解決しない: 現在の製品・OS・移行の方向・状況・期待表示・公式出典をまとめたAI相談文を手動コピーする。個人情報や秘密を自動添付しない。

外部で実行した初期化、番号移行、失効は、アプリの「戻る」や記録の取り消しで逆転しません。外部で何が済んだかを再確認し、現実の状態から続けられるようにします。

## 13. 実装済みの初期経路と残る範囲

2026-11-13時点の初期実装は、主ガイドと別の `deviceWorkflows` に、作業ID・途中位置・戻る履歴・分岐回答・確認記録を保存します。入口は主ガイドの任意作業とSecurity Mapのスマホ詳細です。元の主ガイドのcursor・historyは変更しません。

- 旧データで端末のOSが不明でも、既存IDを再利用して必要な種類だけを質問する。端末や進捗の再登録は求めない。
- 購入前の準備では新端末を作らず、入手後に続きを始める。新旧端末には異なる物理IDを使う。
- 4方向の初期転送の入口を分ける。iPhone同士はクイックスタート、Android同士・iPhoneからAndroidは標準ケーブル経路、AndroidからiPhoneは「iOSに移行」のアプリ経路。無線・QRの新方式・メーカー別・バックアップだけの復元は追加対象。
- 設定済みの新端末は消去せず、利用確認へ進む。中古の所有者ロック、管理端末、紛失・譲渡後は専用の未完了分岐へ進み、売却用の解除を流用しない。
- Google 認証システムは同期／端末内を分け、iOSとAndroidの日本語メニューの違いを反映する。各登録済みAccountで新端末のコードがサービスに受け付けられたことを確認する。未登録・未確認のコードは、手放し前の未完了として残す。
- Microsoft Authenticatorの同じOSでのコード復元と、Bitwarden Authenticatorの端末内／保管庫同期／混在を追加。既存の新端末のコードは残し、本人の実際の同期Account・コードのグループ・正規ログインでの受け付けを確認する。詳細は[認証アプリの機種変更契約](AUTHENTICATOR-PHONE-MOVE.md)。
- 登録したメールAccount、Bitwarden、1Passwordの新端末での利用を確認する。Bitwarden・1Passwordはサーバー認証と保管庫を開く確認を分ける。この確認だけでMFA設定済みにはしない。
- Apple「パスワード」とGoogle パスワード マネージャーのAccount保存では、新端末上の別アプリ実体として、保管庫・同期先・復旧・自動入力・保存パスワードの実利用を確認する。主ガイドの全回答・位置は保持し、端末ロックの重複を省く。詳細と未対応分岐は[組込み管理の実装契約](BUILTIN-MANAGERS-GUIDE.md)を参照。
- SIM・eSIMは新しい回線での通話・SMS確認までを扱う。通信会社別のアクティベーション操作は未実装。iPhoneからAndroidへ移る場合は、使っていた番号のiMessage解除を公式フォームで案内する。
- 新端末のロック・正常なバックアップ・更新を案内し、このアプリの暗号化バックアップを使って案内自体を別端末へ移す条件を表示する。
- 自分で継続利用／予備／未定なら初期化しない。ロック・更新・新端末に頼らない用途の試用・予備の保管を分割した。未定は用途を変えず、操作できない旧端末を使える予備へ変更しない。以前のまとめた確認は保持し、個別の利用観測を捏造しない。売却／譲渡／処分は未完了の移行がない場合にだけ進む。iPhoneの対応世代とPixelの設定アプリからの消去を扱う。その他メーカーの消去は未対応分岐にする。
- 実際の消去等の記録を訂正しても、現実の操作が戻ったとは表示せず、旧端末を利用可能な予備へ自動復帰させない。

Apple・Google組込みの全OS・製品間移行・ローカル保管庫復元、未対応の認証アプリ、MicrosoftのOS間・仕事用等、Googleの複数プロフィール、仕事・学校、銀行、LINEの残る方式・旧端末なし、Signal、決済・交通系・電子ID、メーカー・通信会社固有の経路、紛失・譲渡後の詳細対応、修理・一時貸与は未完了です。利用中の個別項目に確認済み手順がない場合、項目を未完了で残せますが、消去・所有移転の手順は通過できません。これを対応済みの代わりにしません。

## クラウド型パスワード管理の具体化（2026-11-14）

Proton Pass・NordPassの個人用保管庫は、[機種変更の実装契約](CLOUD-MANAGERS-PHONE-MOVE.md)で、既存Account・保管庫・端末上のアプリ、4方向の新端末、別の登録済み端末、旧端末だけで残す選択を具体化します。Account認証、保管庫の読取り、保存パスワードでの新しいログインは個別の確認です。旧端末だけが利用先のまま手放す場合や、解除・復旧手段を用意できない場合に消去へ進めないことを、遷移関数でも検証します。SSO・現在の秘密の紛失・組織共有等を、この基本経路の完了で代用しません。


物理キーの登録・実際の利用の初期経路は[専用契約](HARDWARE-KEY-GUIDE.md)に分けました。新旧端末の既存ガイドを保持した任意作業です。これだけで、キーを紛失した後の交換、全モバイルでの利用、端末内／同期型パスキー全体の移行まで完了したとは扱いません。旧端末の消去の条件を緩めません。


## 2FAS Authの機種変更を追加（2026-11-14）

通常ガイドの必須分岐を増やさず、機種変更時に登録した実際の2FASアプリから始めます。[専用契約TF01〜24](TWOFAS-AUTH-GUIDE.md)に、4方向の暗号化ファイル、同じOSのクラウド同期、既存新端末データを残す経路、復元とコード利用の区別を記載しました。元の基本ガイド全体を保ち、同じ機種変更へ戻ります。完了を取り消した場合や新しい端末を選び直した場合は、旧端末の消去ガードも再評価します。旧端末の継続利用・予備・売却の既存の区別を維持し、36シナリオ全体の完了とは扱いません。

Ente Accountのパスワード・追加認証を旧端末だけに頼れない場合は、[専用契約8節](ENTE-AUTH-GUIDE.md)の復旧を別作業として始められます。使える端末のWebで取り戻したログインと、新しいスマホでの追加認証・データ読取りを分けます。新端末を選んだだけでは移行完了にせず、別Account・固有の認証コードは残します。接続履歴のない初回の全喪失、紛失したパスキーの個別削除、機種変更全体の緊急対応まで一括対応したとは扱いません。
