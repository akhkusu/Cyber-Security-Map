## 今後の実装対象

全候補の詳細は仕様の6〜10章にあります。次を未完了の拡張として管理します。

- mailbox.org、Posteo、WEB.DE、Runbox、HEY、Yahoo! JAPAN、ISP・教育・セルフホスト等の個別手順。
- Google / Microsoft等のパスキー、物理キー、パスワードレスの専用経路。現状の認証アプリ中心のレシピを全方式対応と表示しない。
- 認証アプリ各製品の導入・バックアップ・復元を、OS・製品別にさらに分割する。
- Apple「パスワード」・Google パスワード マネージャーの旧OS・全保存方式・パスキー・製品間移行の拡張。NordPass、Norton Password Manager、Proton Pass、KeePass系、ほかのブラウザー・メーカー組込みの専用経路。候補表だけで対応済みにはしない。
- Bitwarden・1Passwordの既存利用点検、不要なパスワード変更の省略、製品別の認証アプリ選択・復元条件など、補完仕様で追加した不足。
- FileVault / BitLocker等の専用の暗号化設定、予備ディスクへの小規模復元テスト、紛失端末探索。
- ChromeOS、Linux、古いmacOS・Windows、メーカー固有Androidの専用レシピ。現状は確認済み範囲外として分岐する。
- SNS、メッセージ、金融、買い物、ゲーム、ルーター、NAS、ドメイン等。サービスごとの実行可能な手順が揃ってから追加する。
- Mapの認証方式・保存先のノードをさらに細分化し、独立性の確認質問を増やす。
- 実アカウント・実機での画面照合と、利用条件を確認した画像の整備。現在は明示した説明図を使用。

## 検証結果の読み方

- **公式資料確認**: 操作名・順序・適用範囲を公式資料で確認したこと。
- **アプリ経路テスト**: 選択、画面遷移、記録、再開、バックアップ互換性、Mapへの反映をアプリで検証したこと。
- **実機・外部アカウント確認**: 本人の管理する実機・テストアカウントで外部設定そのものを照合したこと。今回、全提供者・全機種でこの検証を完了したという意味ではありません。

通常フローのE2Eでは、外部の説明ページへ移動せずに操作できます。実際の認証設定は、本人が公式の設定画面で行います。
