## 認証アプリの記録の範囲

- アプリの準備・選択だけでは対象AccountのMFAを完了しません。スキャンと、同じ登録操作に対するサービス側の確認を対応付けます。別Account・別アプリや、過去の登録の確認を流用しません。
- 値を持たないコード・端末上のアプリ・対象Account・実際の同期先を区別します。登録時の受け付けは `enrollment` とし、通常／新端末ログインや復元試験へ変換しません。
- 後日の有効状態確認だけでは登録観測の日時を更新しません。再登録は別の値を持たないコードとして扱い、古いコピーの利用観測を未確認に戻します。履歴・バックアップ・未知項目を保持します。
- スキャン・サービス側確認の取り消しは派生する関係・観測も訂正します。外部サービスの認証を無効化したとは表示しません。他の記録に参照される経路を残します。
- Googleの同期先は本人が実際に確認した段階で不足する保護へ接続します。主メールを変更せず、同じAccountのMFA・復旧を再利用します。
- Microsoft・Bitwardenの今回のコードをローカルに保存する選択から、アプリ全体の同期・バックアップなしとは推測しません。今回の機種変更では、アプリ全体の実際の保存方式を別に質問し、確認した範囲の移行・実利用へ案内します。

新しい画面は日英390pxで実際のアプリ表示を撮影・目視確認しています。画像の名前は架空のテストデータで、外部サービスの設定画面を再現したものではありません。

## 旧端末を使い続ける・予備にする経路の追加

通常ガイドと別の任意作業の中で、旧端末のロック、更新画面、提供された更新の適用、新端末を使わない用途の試用、予備の保管を分割しました。「使えました」「保管しました」の一回の操作で記録して次へ進みます。故障・ロック等で操作できない端末は利用可能な予備にせず、可用性を確認し直す入口を備えます。未定は用途を変更しません。

必要な前提を飛ばして用途を確定できません。前提の取り消しで派生する用途の確認も撤回し、別の任意作業の確認は保持します。最後の取り消しは元の用途と未知項目へ戻します。消去前の古い確認を、消去後の確認の取り消しで復活させません。以前のまとめた完了記録は保持し、分割した個別確認を捏造しません。

単体テストではiOS / Android、継続利用 / 予備、故障・未定、既存のまとめた確認、用途変更、前提の取り消し、複数作業の取り消し順序、後の消去との順序を確認しました。ブラウザーでは途中再開、主ガイド全体の保持、予備の記録・取り消し、日英390px・キーボードを追加確認しました。通常URL全57件・Pages配下全61件の後、最後の旧記録・消去順序の修正と文言整理について、該当する通常URLの5件も再確認しています。
