# NordPass個人用保管庫のマスター復旧

資料確認日: 2026-11-14。通常の導入・既知のマスター変更は[CLOUD-MANAGERS-GUIDE.md](CLOUD-MANAGERS-GUIDE.md)、任意の機種変更は[CLOUD-MANAGERS-PHONE-MOVE.md](CLOUD-MANAGERS-PHONE-MOVE.md)を参照する。

## 目的と入口

現在のマスターが分からない利用者が、保管庫の内容と使えるログインを維持したまま、使える復旧方法を選んで進める。通常の保管庫操作・マスター点検・任意の機種変更から、折りたたんだ入口を開く。機種変更のためだけに、設定済みで強いマスターの変更を要求しない。

復旧は独立した任意ガイドで保存する。主ガイドの全回答・履歴・完了記録を上書きしない。機種変更中は、新端末の実際のアプリと結び付け、選択だけをインストール・ログイン・移行の完了にしない。Security Mapの保管庫・関連項目から同じ作業を再開できる。

対象は同一性を確認した個人用Nord Accountを基盤とする既存NordPass保管庫。Nord Account用のパスワード・メールのログインコード、AccountのMFA用10コード、保管庫用マスター、保管庫用24文字のRecovery Code、このアプリの保存用パスフレーズを区別する。

## 必要な分岐

| 状況 | 案内・完了条件 |
| --- | --- |
| 現在の保管庫用コードを取り出せる | 独立したAccount利用と認証手段を確保し、コードを正規アプリで使う。新しいマスターを実際に試す |
| コードはないが、設定済みの生体認証が使える | 実際の同じアカウント・端末・アプリを選び、生体認証で既存項目を開く。そこから新しいコードを発行・私的に保管して続ける |
| どちらもない・分からない | 残るアプリ・セッション・控えを維持して未完了。削除を伴うアカウント全体のリセットを、内容の復旧として案内しない |
| Accountにログイン済み | 正しいアカウントの解除画面かを確認し、不要な再ログインを要求しない |
| Accountのログインが必要 | 対応済みの直接ログインと、必要な既存MFAを一操作ずつ案内する |
| Google・Apple接続で、新しいAccountログインが必要 | [接続の専用契約](NORDPASS-CONNECTED-SIGN-IN.md)に沿い、提供元・Nord認証を分ける。不足は独立した補助ガイドで確認。接続解除・アカウント作り直しを求めない |
| OS・項目・権限・コード・生体認証が想定と違う | その場の案内を表示。解決しない場合にだけ、情報を限定した相談文を本人がコピーできる |

新しい秘密・コード・出目を入力する欄は作らない。紙やPDFの実体を取り込まない。復旧コードは独立した秘密情報であり、実際の値の代わりに、用途・対象・控えの存在・観測だけを保存する。

## 画面の単位と手順

一画面一質問または一操作とし、現在の場所・押す項目・想定表示・次へ進む目安を表示する。資料を外で読まなくても通常の操作を進められる。

1. 必要な場合だけ復旧先のOS世代を確認する。対象は通常の確認済みiOS / Androidアプリ、PCのブラウザープロファイル。
2. 現在使えるコード／設定済み生体認証／どちらもない、から選ぶ。
3. 同じ保管庫の外でNord Accountの利用手段を取り出せるか確認する。機種変更中は旧端末の外でも使える必要がある。
4. 既存のAccount認証・復旧手段を残す。MFAの新設を、この確認で済んだとは記録しない。
5. 生体認証を使う場合だけ、実際の既存アプリを選び、必要なら別の実在端末・アプリを登録する。同じ端末でもネイティブアプリと拡張機能、別のプロファイルは分ける。
6. 生体認証を使う場合は、既存項目の読取り、設定場所、再発行の注意、本人確認、新しいコードの表示、私的な控えを別々に進める。新設が必要な生体認証を、忘れたマスターの代わりに使えるとは扱わない。
7. 現在のコードを独立して確保する。コードをこのアプリへ入力しない。
8. 新しい専用のランダムな語句を準備する。既存のEFF 7776語表・実物サイコロ・6語以上の方法と、製品の文字条件を説明する。例文・AIの提案を実際のマスターにしない。
9. 新しいマスターを私的な紙へ控え、端末から離した施錠場所へ置く。復旧用コードとは用途を分ける。
10. 復旧先のAccountログイン状態を尋ねる。必要なら既存Accountへの直接ログイン・既存MFAを順に行う。
11. 正規のマスター解除画面で、忘れたマスターの復旧を選ぶ。既存のコードを使い、新しいマスターの設定を受け付けられたことを確認する。
12. 通常の保管庫ロックから、新しいマスターを紙から取り出して使い、同じ既存項目を読む。生体認証だけ・開いたままのセッションは、新しい語句のテストにしない。
13. 現在有効なコードの控えを確かめる。復旧後の公式表示等で有効性を特定できない場合は、試して使えた新しいマスターで明示的に再発行する。変更前にコードを受け付けたことだけを、その後の有効性の確認にしない。確認のためのマスターリセットを繰り返さない。
14. 現在の控えを安全に保管したボタン一回で、記録と元の作業への復帰を済ませる。保存サービス用パスワードの実ログインは、別の未完了作業として残す。

上記は画面構成の契約であり、各画面の実際のメニュー名は説明データで管理する。出典と確認日は折りたたみ内に置く。未確認の設定画面画像は追加しない。QA画像は架空の項目名を使った本アプリ自身の画面である。

## 環境差と変更の境界

生体認証の元アプリはiOS / Android、Windows / Macのネイティブアプリ、対応ブラウザー拡張を区別する。MacのSafari拡張で生体認証が使えるとは案内しない。生体認証を利用中のアプリの再インストールやログアウトを、コード確保より先に求めない。

復旧用に登録したネイティブPCアプリを、ブラウザー拡張や自動入力の設定完了へ変換しない。通常の導入で選ぶブラウザープロファイルとは別に残す。登録時点では、元のアプリも復旧先のアプリも未確認である。

コードの再発行は以前の保管庫用コードを失効させる。認識済みの同じ実際の保管庫用Credentialだけを対象にし、Nord AccountのMFA用コード、別Account、意味の分からない旧フィールドを失効させない。個人用コードがマスター復旧後に自動消費・自動再発行されるかは、法人用・MSP向けの別資料から推測しない。

実際のマスター変更は同じ個人Accountの保管庫・アプリの古いアクセス観測を未確認へ戻す。紛失・譲渡・廃止・予備端末という物理的な状態、未知の拡張フィールドは維持する。記録の取り消しでは、実際のマスターやコードを以前のものへ戻さない。古い変更画面へ戻っても、再発行・再設定を重ねない。後の変更に置き換えられた過去の復旧から、古いマスターの利用確認を復活させない。

## 記録と依存関係

コード、マスター、紙の控えを値のない別のEntityで扱い、実際に確認した操作から関係を追加する。コードの受け付け、新しいマスターによる読取り、現在の控えを区別する。生体認証で元端末を開いたことを、新端末で開けた証拠にしない。

完了記録を取り消すと、それに依存した利用観測・関係・Control・機種変更の派生記録を取り消す。参照されているEntity・Routeと、物理的な変更時点は保持する。現在のマスターの確認には、実際の変更後の観測が必要である。古い完了を後の弱いマスターの変更要求へ流用しない。

機種変更の元作業が変更されていない場合、復旧で実施した同じAccount利用、既存認証の確保、マスターと復旧用の控え、同じ新端末アプリでの読取りだけを共有する。別の端末・別アプリへコピーしない。主ガイドの全データを維持し、変更された別の機種変更作業へ結果を押し付けない。自動入力・保存サービス用パスワードの実ログイン・旧端末の消去や譲渡は別の条件である。

normal / new-deviceで観測したものと、all-devices-lostでの復旧を区別する。旧端末なしで新しいマスターを使った確認は、その旧端末に対する独立性の記録であり、すべての紛失条件の保証ではない。コードを使わず新マスターで開いた観測は、コードを後で置き換えても、その置き換えだけを理由に旧マスターへ戻らない。

## 保存・互換性

この機能を始めたときだけモデルrevision 4を使う。暗号化封筒v1・DB・KDF・payload v1 / v2・既存Account ID・完了記録は維持する。新しい作業をsecurityModel.nordRecoveryV1へ版付きで保存し、古いrevisionの意味不明な同名項目は解釈・上書きしない。競合時は元データを保持する。revision 4の作業構造・実際の参照は保存・読込み時に検証する。別のマネージャー・Proton追加パスワード・機種変更を使っても、revisionを下げない。将来の未対応revisionは原本を保持して読込みを止める。

## 相談と残る範囲

通常の作業でAIは不要。画面・項目・コード／生体認証・権限の分岐を表示し、それでも解決しない場合に限り、サービス・OS・検証済みブラウザー種別・作業・現在のステップ・想定表示・困りごと・公式URLをまとめた相談文をコピーできる。呼び名・メール・自由記述・秘密は含めない。最新の公式情報の確認、一度に一質問または一操作、確認できない場合の明示を指示する。画像の秘密・個人情報を隠すよう案内し、外部AIへ自動送信しない。

新規SSO専用Account・接続解除／置換・未確認の接続経路、法人管理の復旧、削除後の復元、全端末・全コードを失った場合、全旧OS、製品間移行は残る。アカウント全体リセットで既存項目を回復できたとは表示しない。到達仕様196条件や他の製品対応全体を、この追加だけで完了とは扱わない。
