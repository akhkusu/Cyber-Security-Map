# Proton Passの任意の追加パスワード

追加パスワードの操作資料確認日: 2026-11-14。通常の保管庫は[CLOUD-MANAGERS-GUIDE.md](CLOUD-MANAGERS-GUIDE.md)、スマホの引き継ぎは[CLOUD-MANAGERS-PHONE-MOVE.md](CLOUD-MANAGERS-PHONE-MOVE.md)も参照します。

## 入口と対象

個人用Proton Passの「重要なログインを保存して使う」画面に、折りたたんだ任意の入口を置きます。Mapで実際の保管庫・アプリの手順を開いた場合も利用できます。既存の完了済み利用者へ、新しい必須設定や再登録を要求しません。通常のProton Account用パスワードとMFAを維持する選択もあります。

対象は既存の個人用保管庫、確認済みのiPhone / iPad・Androidアプリ・PCのブラウザー拡張です。実際の端末・プロファイル・基盤Accountを維持し、別Accountへ設定や確認をコピーしません。組織・共有の専用管理や、Protonの旧来のtwo-password modeの専用手順を追加対応済みとはしません。

追加パスワードは、Proton Accountのパスワード、AccountのMFA、このアプリの保存用パスフレーズとは別のものです。パスワードを二つ使うことからMFAが有効とは記録しません。標準のProtonログインに、必須の新マスターを作らせる機能ではありません。

## 表示を確認して分ける

まず既存の設定画面を開く一操作だけを案内し、次の画面で未設定／設定済み／現在の秘密が分からない／項目が見つからない、を本人に確認します。選択だけでは設定完了を作りません。実際の未設定の表示を回答して通常設定を維持する場合は、その一回の選択で確認の記録と元のガイドへの復帰を行い、同じ確認を別画面で重ねません。

| 表示・選択 | 実際に記録すること | 記録しないこと |
| --- | --- | --- |
| 未設定のまま使う | 正規画面で現在の未設定を確認した記録 | MFAなし・危険という判定、新しい認証の成功 |
| 設定済みを維持 | 現在の有効表示と私的な紙の控え | 追加パスワードでの新しいログイン成功 |
| 新しく設定する | 以下の準備、正規設定の受け付け、Account認証、追加パスワードの受け付け、既存項目の読取りを個別に記録 | 保存したサービス用パスワードの利用、全端末喪失からの復旧 |
| 秘密・表示が不明 | 未完了と途中位置 | リセット・解除の成功、利用可能な予備の捏造 |

## 新しく設定する順序

1. Passの外から、現在のProton Accountのログイン情報を取り出せるか確認する。
2. 同じPass保管庫を開かなくても、AccountのMFAまたは提示された既存の復旧方法を利用できるようにする。唯一の認証コードがPass内にある循環を解決してから続ける。
3. 現在のProton復旧フレーズ・Recovery Kit・復旧ファイルをProton外に確保し、追加の復旧先を利用できるか確認する。有効な控えを再発行しない。
4. 追加パスワード専用のランダムな語句を用意する。製品の8文字という最低条件と、十分な強度の推奨を区別する。共通のEFF単語表から物理サイコロで6語以上を無作為に選ぶ方法、またはすでに使える信頼できる生成機能を案内する。例文・AIの提案をそのまま使わない。
5. 「Proton Passの追加パスワード用」と用途を書いた私的な紙の控えを作る。Passとスマホの外の施錠できる場所へ置き、Account用・MFAコード・本アプリ用の秘密と分ける。唯一の控えを同じPassや同期写真へ置かない。
6. 選択中のアプリ・拡張機能の追加パスワード設定を開く。
7. 正規の入力欄で新しい語句と確認用の語句を入力し、最後の確定の前で止まる。
8. 独立した控えと認証手段を再確認して、公式の確定ボタンを押す。全端末のPassからサインアウトされることを、確定前の画面内で説明する。
9. 同じアプリ・拡張機能へ、既存Accountのユーザー名とAccount用パスワードでログインする。
10. 求められた既存MFAを行い、Passの追加パスワードの表示へ進んだことを確認する。Accountの認証をここで別に記録する。
11. 紙の控えから新しい追加パスワードを取り出し、Passの専用欄だけで使う。受け付けを別に記録する。
12. 同じ保管庫の見覚えのある既存項目を開き、読めることを確認する。データは維持する。
13. 通常の保存ログインの手順へ戻り、重要なサービスで保存済みのパスワードを実際に使う。

各番号は独立した操作画面です。実際の語句・コード・復旧情報・出目は、本アプリへ入力しません。設定後に戻って手順を見直した場合は、現在の設定と控えを確認する文章に切り替え、別の語句の作成・再設定を繰り返させません。

## プラットフォームごとの違い

| 環境 | 開く場所 | 最後の確定 |
| --- | --- | --- |
| PCのPass拡張 | 3本線メニュー → Settings → Security → Extra password。追加の保護を選び、入力・Continue・確認欄へ | Set extra password |
| Android / iPhone / iPad | Profile → Account名 → 3点メニュー → Manage account → Set extra password。新しい語句と確認用を入力しContinueへ | Confirm |

実際の英語項目は公式資料で確認した名称を示します。端末内にない項目や、未確認の同名のリセットへ誘導しません。説明図・第三者の設定画面画像は今回追加していません。保存するQA画像は、架空の呼び名を使った本アプリの画面です。

## 同一Account、観測とMap

設定変更は同じ実際のProton Accountで利用するPass全体に作用します。選択中の保管庫だけでなく、その同じAccountを基盤とするPass保管庫・端末上のアプリの古いアクセス観測を失効の時点から未確認にします。別のProton Accountや、AccountのMFA・Mail自体の設定完了は変更しません。すでに記録した紛失・譲渡・削除などの用途や状態も維持し、設定変更だけで利用中へ戻しません。

追加パスワードは値を持たないCredential、紙の控えはData setで表し、紙へ保管した操作を確認して初めて関係を記録します。設定済みの同じ秘密・同じ紙の控えを確認した場合は、確認済みの同一性の範囲で再利用します。Accountの認証、Passの追加パスワードでのログイン、保管庫の読取りは別の観測です。

追加パスワードでPassへログインできても、「保存したサービス用パスワードを利用した」とMapへ表示しません。後者には、実際の保存Credentialを使った専用の観測が必要です。追加パスワードのノードには、新しいログインで使った記録の有無を表示し、設定や紙の控えだけを利用成功にしません。

新しい利用観測の文脈はnormal / no-existing-sessionです。依存先の完全な調査、全端末喪失からの復旧、あらゆる紛失条件への独立性とは扱いません。仕組み・知識要素とMFAの違い・開いたセッションや端末侵害に対する限界は折りたたみで説明します。

## 再開・取り消し・保存

作業の要求ごとに別のキーを発行し、実際のアプリと結び付けます。再読込みでは同じステップへ戻り、後回しでも同じ要求・語句の準備を再利用できます。以前の確認画面を戻って開いても、古い変更要求を現在のものへ復活させません。

各操作を完了記録から取り消せます。前提を取り消すと依存する確認・関係・観測も未確認へ戻します。参照されるCredential・Routeを削除しません。実際の設定変更を受け付けた時点は保持し、履歴の訂正で秘密が以前のものへ戻ったとは表示しません。実際に変更した後は、準備の記録を訂正しても、現在の秘密での再ログインと保存の続きへ進めます。

この機能へ初めて入る場合だけモデルrevision 3へ拡張し、revision 2までの旧版による誤解釈を止めます。既存のrevision 1 / 2、暗号化封筒v1、KDF、DB、AccountのID、完了記録、未知項目を維持します。新しいCredentialや紙の控えの意味は版付きの識別子がある項目だけで解釈し、古い不明な同名項目を復旧手段へ変換したり失効させたりしません。新しいキーと不明な従来の回答が衝突する場合は上書きせず、原本の暗号化バックアップを案内します。別のマネージャーや機種変更を後から使っても、revisionを下げません。NordPass復旧のrevision 4を利用済みの場合は4を維持します。

## 未確認の復旧と残る実装

公式の追加パスワード記事には、忘れた追加パスワードを復旧する具体的な手順がありません。Account用の復旧フレーズや、72時間のsigned-in resetが、その秘密も復旧できるという根拠にはなりません。現在のセッション・控えを残して未完了にし、その場の表示・利用環境を確認します。解決しない場合だけ、製品・確認済みOS／ブラウザー・作業・期待表示・困りごと・公式資料を含む、秘密と呼び名を除いたAI相談文を手動でコピーできます。

追加パスワードの解除・置換・紛失からの復旧、組織・共有、旧two-password modeの専用経路、実機ごとの画面照合は追加対象です。今回の有効化と設定確認の完了から、それらまで完了したとは表示しません。
