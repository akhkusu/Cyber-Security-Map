# Apple・Google組込みパスワード管理の実装契約

更新日: 2026-11-13。この文書は[製品別補完仕様](PASSWORDS-AUTHENTICATORS-SPEC.md)のP5・P6と、[機種変更仕様](DEVICE-CHANGE-LIFECYCLE-SPEC.md)の実装範囲・境界を具体化します。全方式・全OSの完成を意味しません。

## 1. 利用者の導線

主ガイドのパスワード管理で、Bitwarden・1Passwordに加え、Apple「パスワード」とGoogle パスワード マネージャーを選べます。選択だけでは、導入・保護・保存・ログインを完了にしません。

1. 登録済みの保管庫を再利用するか、実際に使う別の保管庫を追加する。
2. 使う物理端末を既存の項目から選ぶ。なければ追加する。端末上のアプリは、保管庫と端末の組み合わせごとに区別する。
3. AppleではOS世代、GoogleではAccount保存／端末内保存を、必要になってから確認する。
4. Account保存では、実際の基盤Accountを選ぶ。同じメール用Accountなら同じIDを使う。別の個人用・仕事用は分ける。
5. 基盤AccountのMFA・復旧が未完了なら、その不足する設定のガイドへ進み、完了後に自動で戻る。既存の記録は再実施させない。
6. 正しい保管庫を開く、端末ロック、未ログインの場合だけ正規の端末／Chromeログイン、保存先、独立した復旧用情報、自動入力を一つずつ確認する。
7. 重要なアカウントの現在の項目を保存・確認する。すでに固有のランダム生成パスワードなら、変更を省略して実ログインへ進める。
8. 変更する場合は、旧パスワードの安全な一時控えを確保し、公式の変更画面を開き、製品の生成機能を使う。サービスが受け付けてから保存項目を更新する。
9. 現在のセッションを残した別の画面で、正しい保存項目を使ってログインする。この一回の確認で作業を記録し、次の端末対策へ進む。

専用マスターパスワードは作らせません。このアプリの保存用パスフレーズ、Apple Account／Google アカウントのパスワード、端末のパスコード、Google パスワード マネージャーのPINは同一の秘密として扱いません。パスワード・コード・復旧情報そのものは収集しません。

## 2. 公開した経路と境界

| 製品 | 組み込んだ経路 | 留意点・未実装 |
| --- | --- | --- |
| Apple「パスワード」 | iOS／iPadOS 18以降、macOS Sequoia 15以降。アプリの解除、iCloudの保存先・同期、自動入力、保存・生成・実利用 | 旧OSの設定アプリ経路、WindowsのiCloud、全パスキー・確認コード・共有・移行は追加対象 |
| Google パスワード マネージャー | ChromeのAndroid・iOS・デスクトップ経路。Account／端末内を区別。公式インストール先、保存先、生成・保存・実利用 | Android・iOS・WindowsはアプリE2E対象。Mac・Ubuntu・ChromeOSの製品選択とChrome手順はあるが、個別実機・全経路E2Eは未完了 |
| Googleの端末内保管庫 | 保存方式を選び、書き出し設定と暗号化した独立コピーの前提を表示 | 暗号化保存先を新規に作るOS別ガイド、取り込み・復元テストは未実装。コピーを取り出せた記録を、復元成功とみなさない |
| 機種変更のApple | 旧端末で使った保管庫を、新iPhoneの別アプリ実体として開き、同期・復旧・自動入力・保存パスワードの利用を確認 | iOS 18以降。Androidへの製品横断移行は未完了として消去を止める |
| 機種変更のGoogle | Account保存の同じ保管庫を、新Android／iPhoneの別アプリ実体で確認する | ローカル保存の復元、別製品との取り込み、パスキーの復号条件は追加対象 |

Chromeの現行インストール資料は、Android 10以降、iOS／iPadOS 18以降を対象としています。画面が違う、ストアで非対応、権限がない場合に、データ削除や管理解除で合わせる操作はさせません。[Android](https://support.google.com/chrome/answer/95346?co=GENIE.Platform%3DAndroid&hl=ja)、[iPhone／iPad](https://support.google.com/chrome/answer/95346?co=GENIE.Platform%3DiOS&hl=ja)。資料確認日: 2026-11-13。

Chromeの書き出しは方式を区別します。CSVは読める秘密情報なので、通常フォルダーやメールへ出さず、保護された暗号化保存先を先に確保します。安全な保存先を選べない場合は止めます。アプリ間の認証付き転送とCSVを書き出す操作を混同しません。[PCの書き出し](https://support.google.com/chrome/answer/13068232?co=GENIE.Platform%3DDesktop&hl=en)、[Androidの書き出し・取り込み](https://support.google.com/chrome/answer/13068232?co=GENIE.Platform%3DAndroid&hl=ja)。後者には現行の認証付きアプリ間転送も記載されていますが、その全方式はまだアプリへ組み込んでいません。

## 3. Account・保管庫・端末上のアプリ・保存手段を分ける

- 既存の `assets` のAccount・物理端末を正規の実体として再利用する。組込み管理を選んだだけで、マネージャー用の偽Accountを増やさない。
- v2の `vault` は製品、保存方式、実際の基盤Account参照を持つ。同じ製品でも別Account・別ローカルプロフィールは別保管庫にする。
- `installation` は物理端末と保管庫を参照し、その端末での開封・保存先・自動入力・実ログインの確認を持つ。別端末へ完了状態をコピーしない。
- 実際に保存パスワードでログインしたときだけ、値を持たない `credential` と、保存先・認証先の関係を記録する。
- Accountのパスワード変更は、過去のログイン観測を無効化するが、端末上で保存内容を読めた過去の観測まで同じ意味で扱わない。ログインと保管庫の復号は別経路にする。
- 確認記録を取り消すと、その記録で確定した関係を撤回し、該当観測を未確認に戻す。他の経路から参照される観測・経路そのものを消して参照切れにしない。

モデルの参照IDは主ガイド・機種変更・Security Mapで共通です。表示用の互換アダプターは、一時的な描画データに限り、Accountとして永続化しません。旧v1は従来どおり利用でき、新機能を選んだ時だけ、安全にv2へ拡張します。

## 4. 機種変更の完了条件

機種変更の回答は、主ガイドの `cursor`・`history`・`answers`・既存の完了記録を変更しません。新端末に同じAccountを選んだだけで、保管庫を開ける・保存情報を使えるとは扱いません。

新端末用アプリを選ぶ → 実際に開く → 保存先と基盤Accountを確認 → 旧端末だけに頼らない復旧用情報を確保 → 自動入力 → 実際に保存した重要Accountを選ぶ → 正規サービスでその保存パスワードを利用する、という流れです。パスキーでログインできた場合は、保存パスワードを確認した記録の代わりにしません。

同じ新端末の画面ロックを、この操作と後続の一般端末対策で二度要求しません。取り消し後は必要な確認を復活させます。新端末を選び直した場合は新しいアプリ実体を使い、元の確認記録は履歴として残します。

ローカル保管庫、AppleからAndroidへの移行、未登録・未対応の保存Account、基盤Accountの未完了な復旧等は、消去前の未完了一覧に残ります。旧端末を手元に残す選択はできますが、未確認の移行を完了として消去・譲渡へ進めません。

## 5. Security Mapでの意味

保管庫、端末上のアプリ、値を持たない保存パスワードを別ノードにします。Accountの再利用・アプリの場所・保管庫の同期先を選んだだけでは、確認した線を描きません。実際の操作を確認したときにだけ線を増やします。

「利用の記録あり」は、その端末の保存情報を使った記録です。少なくとも1台の同じアプリ実体で必要な確認が揃った場合にだけ、保管庫全体へその旨を表示します。異なる端末の部分的な確認を寄せ集めて完了にしません。端末を失う想定は、確認した利用経路で必要になる端末へ作用します。復旧・全端末喪失で使えるかは、通常のログイン成功だけでは確定しません。

型付き実体の描画・閲覧は追加しましたが、全分類の登録・編集・アーカイブ、独立した復旧経路や共通障害の質問は未完了です。

## 7. 検証契約

- 実アカウントの同一性、保存方式変更、別Account選択、別端末、OS世代違いで、完了記録を誤って共有しない。
- 複数ガイドで確認した同じ画面ロックは、最後の確認を取り消すまで保持する。
- 設定更新でアプリの既存カーソルが消えず、暗号化して閉じた後に同じ操作へ戻る。
- 確認の取り消しは観測を未確認にし、他の観測・モデル参照・現実の操作を巻き戻さない。
- 通常経路で外部説明ページを読ませず、必要な公式設定先・ダウンロード先を開ける。AIへの自動送信はない。
- 主ガイド5経路と新スマホ3経路をブラウザーで検証し、390px・日英・キーボード・Pages配下・旧データ互換性も確認する。実施結果と未確認の範囲は[実装状況](IMPLEMENTATION-STATUS.md)へ記録する。
