# LINEを新しいスマホで使うためのガイド

版: 1.1 / 資料確認日: 2026-11-14 / 状態: 初期QR経路を実装、全LM条件は継続中

[機種変更・旧端末の扱い](DEVICE-CHANGE-LIFECYCLE-SPEC.md)のPH18・PH22〜25・PH30〜36を具体化する到達仕様です。製品一覧と初期QR経路をアプリへ接続しました。以下の到達仕様全体や資料調査を、実機での移行成功・全方式の対応済み表示へ置き換えません。通常の基本対策へ必須の質問は増やさず、本人が機種変更・旧端末の整理を始め、LINEを使っている場合だけ表示します。

## 1. 到達状態と、別々に確かめること

一つの「LINE移行済み」でまとめず、次を独立して記録します。

| 対象 | 本人が確認する到達状態 | それだけでは足りないもの |
| --- | --- | --- |
| 同じLINEアカウント | 新端末で意図した既存アカウントを開ける | アプリをインストールした、似たプロフィール名が表示された |
| 今後の利用 | 新端末で必要なトークを開ける。受信等の本人が必要とする利用ができる | ホーム画面に到達しただけ |
| 残したい履歴 | 選んだ期間・種類のデータを新端末で実際に開ける | バックアップのスイッチがオン、画像の小さなプレビューがある |
| 移行後の復旧 | 今後使える認証・復旧先を確認し、旧端末だけへの依存を残さない | パスキー名が一覧にある、旧端末にだけパスワードが保存されている |
| 旧端末 | LINEのメイン／サブの実際の状態と、残す用途・手放す条件が分かる | 物理端末を残したのでLINEも予備として使える、という推測 |

LINEから新規アカウントを作る作業へ自動で切り替えません。引き継げない場合は、元のアカウントの復旧・調査と、本人が別途選ぶ新規作成を区別します。新規作成を移行成功と数えません。[L02]

## 2. 機種変更ガイドに戻れる入口と利用項目の確認

既存の `special-apps=yes` は「製品が分からない未完了」です。これをLINEだけの利用や移行完了へ読み替えません。既存の `none` も、後から登録した対象や未完了の実際の依存を打ち消しません。

1. 既存Mapの旧端末に結び付く製品を候補として示し、使っているものを本人が確かめる。
2. 製品が未登録なら、必要な時点で一つずつ追加できる。最初に全サービスの登録を求めない。
3. LINE、Signal、WhatsApp、決済・交通系、銀行、電子ID、仕事・学校、その他を区別する。未対応製品をLINE手順で処理しない。
4. 「ほかにもある」「分からない」は未解決の項目として残す。何も選ばなかったことを「使っていない」とは扱わない。
5. 各製品の作業を終えたら同じ機種変更の次の必要な項目へ戻る。通常ガイドの回答・履歴・途中位置を変更しない。
6. 一製品の完了で `special-apps` 全体を完了にしない。後回しでも新端末の独立した準備は続けられるが、未解決の旧端末依存を残して消去・譲渡へは進めない。

製品ごとに選択済み／準備中／引き継ぎ実行済み／利用確認済み／履歴の一部未確認／後回しを表せます。画面の主ボタンは、その操作の記録と次の一画面への移動を一回で済ませます。

## 3. 必要になった時点で聞く情報

既存の物理端末・アカウントIDを再利用します。答えが既にある場合は繰り返しません。事実が変わっている場合は訂正できます。

| 質問 | 必要な分岐と扱い |
| --- | --- |
| どのLINEアカウントか | 既存の実際のアカウント／別アカウント／まだ区別できない。同名のアカウントを統合しない |
| 旧端末でLINEが使えるか | 端末が手元にあることと、対象LINEへアクセスできることを別にする。サブ端末だけを持つ場合も分ける |
| 旧新のOS・LINE版 | 4方向、機能に必要な版、既に新端末を設定済みか。OS転送とLINE移行を同じ完了にしない |
| 新端末の現在の画面 | 初回／クイックスタート後の本人確認／既存の同じLINE／別のLINE／不明。既存データを守る |
| 何を残したいか | アカウント利用、直近の履歴、それ以前の文章、写真・動画・ファイル等。具体的な内容や相手の名前は入力させない |
| 利用中のバックアップ | 標準／プレミアム／未使用／不明、最後に正常終了したか、使った実際のクラウドAccount |
| 今後使うログイン方式 | QR、既存パスキー、同じ番号、変更する番号、設定済みのApple／Google連携。今使えるものだけ提示 |
| 回線と認証の状態 | 番号が同じか、必要なSMSを受けられるか。番号自体は保存しない。回線移行の記録と再利用できる範囲を分ける |
| 旧端末の今後 | 継続利用・予備・手放す・未定。LINEのサブ端末可否と物理端末の用途を混同しない |

国・地域は、番号方式・プレミアム等の適用判定に必要なときだけ選択式で聞きます。端末の言語と、アカウントの提供地域を同一視しません。最新機能の版が使えない場合は、既存の利用可能な別経路・準備の保留へ進みます。

## 4. 現在の対応条件と引き継ぎ方式

| 方式 | 経路を出す前の条件 | 完了後も別確認するもの | 出典 |
| --- | --- | --- | --- |
| かんたん引き継ぎQR | 両端末が手元にあり接続でき、旧メイン端末で対象LINEを利用できる | 履歴の範囲、旧メインのログアウト、変更後の電話番号 | L03 |
| パスキー | LINE26.17.0以上、対象Accountへ事前登録した鍵と、実際に使える保存先 | Accountへのログインと履歴復元、保存先の復旧を別記録 | L08・L09 |
| 同じ番号 | 対応地域、登録済みの同じ番号でSMSを受信でき、必要な既存パスワードを利用できる | PINと履歴、旧端末の利用終了 | L10 |
| 異なる番号 | 実際の回線状態と登録済みの認証方法を確認 | 別人のAccount表示、追加の引き継ぎ認証、番号更新 | L11 |
| Apple／Google連携 | 対象LINEと事前に結び付けた実際の提供元Accountへ入れる | 引き継ぎ認証、プレミアムのパスワードと履歴 | L12・L13 |
| iPhoneのクイックスタート後 | 新端末に該当する本人確認画面が実際に出た | OS移行だけでLINEを利用済みにしない | L04 |
| GalaxyのSmart Switch後 | 対応地域・機種・転送経路を確認 | メーカー転送後にも必要なLINEの本人認証 | L15 |

L01の確認時点では、最新版の推奨環境はiPhoneがiOS18以上、AndroidスマホがAndroid11以上です。以前のOS向けの利用可能な旧版も別に記載されています。古いQR紹介にある最低版を、現在インストールできる版の条件に流用しません。アプリ版・OS・機能の条件を別々に判定し、日付を持つデータとして更新します。[L01]

LINEの「2段階認証をスキップ」は、一般のメール等のMFAを解除する作業ではありません。選んだLINEの引き継ぎ方式に関係する一時的な設定として説明し、QR・同じ番号の経路では要求しません。必要な場合も36時間の条件と、オンにしないで進める追加認証の経路を扱います。期限切れを完了にせず、旧端末がない人に今から旧端末で有効にさせません。[L13]

## 5. 残したいデータと保存方法を先に合わせる

| 保存・移行方式 | この仕様で別々に記録する範囲 | ガイドの条件 |
| --- | --- | --- |
| QRによる直近の移行 | 直近14日分の履歴・メディアと、それ以前の未移行分 | 14日で足りるかを実行前に確認する。全期間の復元という表示にしない |
| バックアップ用PIN | 事前設定したPINで扱える直近の履歴 | LINEの6桁PINを正規アプリだけで作成・確認。端末PIN・マスター・本アプリの保存用語句とは別 |
| 標準バックアップ | 同じOSで復元する文章、iOSのiCloud Drive／AndroidのGoogle ドライブ、実際のAccount | OSをまたぐ復元や、過去の全メディア保存へ広げない。正常終了を確認 |
| プレミアム | 実際に保存対象に入った履歴とメディア、初回バックアップの終了 | 利用地域・契約・必要版、未保存項目・復元中・除外を確認。開始しただけでは移行へ進めない |
| アプリ外へ保存 | 本人が必要なデータを別の保存先で開ける | LINE内の復元とは別。書き出した文章や写真だけでトーク全体を復元できたとしない |

QR・PINの範囲はL03・L06、標準の条件はL05、プレミアムの条件はL07で管理します。異なるOSでは購入済みLINEコイン等、履歴以外にも引き継げない対象があります。利用している人だけ、本人の必要な対象と公式の対象表を照合します。[L14]

プレミアムも、保存前に期限切れ・未ダウンロードだったメディアまで取り戻す保証にはしません。初回未完了、容量不足、除外した項目、契約終了後の保存期限を状態として残します。また、引き継ぎ中のLINEパスワード再設定でバックアップが削除される条件があるため、単に「忘れたら再設定」へ進ませません。現在のバックアップを守れる準備・公式の該当経路を先に確認します。[L07]

本人の保存希望を満たせない場合は、その場で「この範囲を残す方法を確認する」「移行を後回しにする」「この範囲は移さない」を選べます。後者は対象と説明を明示して記録し、復元成功には変換しません。一般の「次へ」やAI相談文のコピーを、データ喪失への了承にしません。既に起きた消失は移行前の選択として遡って記録せず、未確認・失われた状態として残します。

## 6. 最初に公開するQR経路の画面契約

これは両端末を利用できる本人の既存LINEを引き継ぐ経路です。実装時には表の各行を独立した画面にし、必要な前提だけを表示します。複数のタップがある行も、一画面一操作へ分割します。

| 段階 | 操作する場所・案内 | 次へ進む条件と例外 |
| --- | --- | --- |
| 準備 | 残したいデータの範囲と保存方式を選ぶ | 該当するバックアップ・PIN・別保存の子手順を先に終える |
| 保存確認 | 旧端末のLINEでバックアップの結果を読む | 正常終了・必要な保存先を本人が確認。実行中・不明では先へ進めない |
| 新端末の入口 | 新端末のLINEで既存Accountへのログインを選ぶ | Androidで端末の役割を聞かれた場合だけメインを選ぶ。別Account使用中なら止める |
| スキャン画面 | 新端末でQRによるログインを選び、スキャン画面を開く | 必要な正規の権限がない場合は、その権限だけを扱う例外へ進む |
| QR表示 | 旧端末のLINE設定から引き継ぎ用QRを表示する | プロフィール追加用・サブ端末用のQRを使用しない。アプリへQRを入力・画像添付しない |
| 読取り | 新端末で旧端末のQRを読み取る | 期限切れ・失敗はQRだけ再表示。保存済みデータや過去の他Account作業を消さない |
| 旧端末の承認 | 本人が今スキャンしたことを旧端末で承認し、求められた端末認証を行う | 身に覚えがなければ承認せず止める。本人認証の値はLINE／OS内だけ |
| Account確認 | 新端末に表示された対象が意図した既存Accountかを確かめる | 違う・分からない場合はログインを確定させない。表示名・写真をこのアプリへ取り込まない |
| 切替の前 | 旧メイン端末で使えなくなることと、済んだ準備を短く表示する | Account確認・必要な保存結果・受け入れた対象外が揃うまで、切替操作を案内しない |
| 切替 | 新端末で対象Accountへのログインを確定する | 送信前／操作したが結果不明／旧側利用終了を含む実行結果を区別。戻るだけで再実行しない |
| 履歴 | 選んだ方式の履歴復元へ進む | 復元する／しないの意味を反映。標準・プレミアム・実際のOSで分ける |
| 復元中 | 復元の進行を新端末で確認する | ホームに入れただけでは履歴を完了にしない。中断・除外・部分復元へ分岐 |
| 実利用 | 対象Accountと必要なトーク・保存対象を新端末で開く | 内容・連絡先・会話は入力させない。目的に必要な範囲の本人確認を記録 |
| 今後の利用 | 番号を変更した場合だけ登録番号を確認・変更する | 実際の回線と正規のAccount設定を結ぶ。番号自体を保存しない |
| 旧端末 | 同じAccountの旧メインが利用終了したか、今後の用途を確認する | 旧端末を残してもLINEの有効な予備とは推測しない。別の用途は維持 |
| 戻る | 同じ機種変更の次の必要な項目へ進む | LINEのみの結果を反映。未完了の別製品・元の主ガイドは保持 |

L03とL04では、旧端末が使えなくなる説明の位置・表現が異なります。アプリは「復元直前までは必ず旧端末を使える」と仮定せず、QR読取り前に保存を終え、遅くとも新端末のログイン確定前に影響を示します。実際に現れた表示で経路を選び、未確認の版の切替時点を断定しません。

## 7. パスキー・番号・連携を使う経路

### 7.1 パスキー

- 登録は旧メインのLINE設定からAccountのパスキーへ進む。作成を選び、正規の保存先で本人認証する。すでに有効なら変更を強制せず、対象・保存先を確認する。[L08]
- LINEはPRF対応の保存先を必要とする。製品名だけで対応とせず、OS・アプリ版・実際の受け付けを確認する。[L08]
- 新端末では既存Accountへのログインから別方式を選び、パスキーの経路へ進む。どの保存先と実際の鍵を使ったかを記録し、Accountに入れた後で履歴を確認する。[L09]
- 同じOS／同じ同期先でも、鍵の一覧が見えるだけでは新端末で利用成功としない。異なるOSでのOS・保管庫間コピーは、その製品の正確な操作が照合できるまで未対応として残し、QR等の使える別方式を案内する。
- 同じ鍵のコピーと、LINEへ別に登録した独立の鍵は別。コピーを復旧手段の本数へ加算しない。保存先の鍵削除とLINE側の登録削除も別作業として扱う。

L08にあるiOS26以降・対応するAndroidのシステム更新の説明だけでは、OS側のコピー／書き出し項目名まで確定できません。CSVのパスワード書き出しをパスキー移行として案内しません。Apple・Google・選んだマネージャー側の一次資料と実際の対応が揃ってから公開します。

### 7.2 同じ番号・変更する番号

新端末の実際の画面に合わせ、既存Accountのログイン、方式選択、国・番号の入力、SMS受信、表示Accountの確認、既存パスワード、引き継ぎ認証、履歴復元を分割します。番号・コード・パスワードは正規のLINEだけへ入力します。[L10・L11]

番号が変わる場合、表示された別人のAccountを自分のものと認めさせません。自分のAccountを選び直す正規の分岐へ戻します。旧端末がない、SMSが来ない、パスワードを忘れた場合は、登録済みの別方式とバックアップへの影響を確認し、未確認の新規作成やリセットへ誘導しません。

### 7.3 Apple・Google連携

LINEの既存連携先と、OSにログイン中のAccount、履歴保存用のAccountは同一とは限りません。実際にどれを使うかを本人が選びます。必要な引き継ぎ認証と、プレミアム復元時に求められる既存LINEパスワードを別の操作にします。Apple／GoogleへログインできたことだけをLINEのデータ読取り成功にしません。[L12]

提供元の認証が不足している場合は、同じ実際のAccountのガイドへ寄り道できます。終わった後は、このLINE作業と同じ機種変更へ戻ります。プロバイダーの一般MFA、LINEの一時的な引き継ぎ認証、端末の生体認証を同じ設定として扱いません。

## 8. 旧端末を残す場合

| 本人の目的 | 案内の条件 |
| --- | --- |
| 旧端末もスマホとして使う | LINE以外の写真・回線・認証等の用途を維持。LINEメインの移行で端末全体を消さない |
| 旧Androidで同じLINEを使う | 対応版と実際のメイン／サブ選択を確かめ、サブ端末の別作業へ進む。既存データがある場合は上書き前に止める |
| 旧iPhoneをLINEの予備にする | iPhoneはサブ端末にできないという公式の条件を示す。旧メインが自動的な有効予備になるとは記録しない |
| 旧端末を保管する | 電源・解除・更新・必要なネットワークと実際にできる用途を確認。LINEを開けない予備をLINE復旧可能と数えない |
| 手放す | LINEの確認だけで全端末を消去可能にしない。別製品・回線・本アプリの移行・所有解除の既存条件へ戻る |

メイン／サブの適用と制限はL02・L16を参照します。サブ端末を持つことと、旧メインなしでAccount引き継ぎや履歴バックアップができることは別です。サブへの再ログインが必要な場合も、メインの引き継ぎ完了を巻き戻しません。

## 9. 状態、互換性、Security Mapへの反映

既存の `phoneSchemas.ts`・`phoneEngine.ts`・`phoneCatalog.ts` とモデルrevision12までを照合し、初期実装をrevision13の `securityModel.linePhoneV1` に分離しました。以下は、残る方式も含む到達契約です。

- 機種変更ID、製品作業ID、実際のLINE Account ID、旧新の物理端末ID、端末ごとのアプリ実体、元のガイドと戻り先を識別する。
- 方式・OS・版・資料版、保存希望・保存結果・復元結果・明示した除外、バックアップの保存先Accountとデータ集合を別にする。秘密値・会話内容は保持しない。
- Accountの役割移転、旧メインの利用終了、実際のログアウトを履歴として残す。実行前・送信後結果不明・適用を区別し、保存失敗や再開で外部操作を重複させない。
- 旧端末の操作可否とLINEセッションの可否を別に持つ。LINEの旧側ログアウトから端末全体の紛失・消去・他アプリ失効を推測しない。
- 過去の完了を訂正しても物理的な切替は逆転しない。未確認の現在状態から確認を再開し、古い利用実績を復活させない。
- 新端末を選び直す場合、前の端末で確認した実績を新候補へコピーしない。実際の切替結果は元の端末と試行へ結び付けて残す。
- 同じ実際のAccountを別の作業から扱う場合、現在の有効な実績を共有する。新しい物理端末・別Account・別データ範囲へ拡大しない。
- 旧v1・モデル1〜12、未知項目、既存の `special-apps` 回答と記録、封筒・暗号化バックアップを保持する。必要なら新モデルへ明示的に拡張し、未知の同名ストアを上書きしない。
- 説明文や出典の更新だけで、既存の正常な完了記録を一律に消さない。破壊的な方式差は適用条件と現在状態を再評価し、再登録の強制へ変えない。

Mapでは、本人が確認したAccount・アプリ・端末・バックアップ・保存先・ログイン方式の関係を表示します。旧メイン利用終了、新端末の利用確認、履歴の一部未確認、依然旧端末にしかないものを別ラベルで示します。未確認の線は確定せず、色の根拠から該当ガイドへ移動できます。「LINE対応済み」の緑一色で残る履歴・復旧の条件を隠しません。

## 10. 例外、技術解説、日英の文言

## 12. 初期実装と残る方式

### 12.1 接続した範囲

- 通常ガイドの位置を保つ任意の機種変更から、製品一覧へ進めます。LINE・Signal・WhatsApp・銀行・決済・交通系・電子ID・仕事・その他・不明を分け、未対応の製品は未完了で残します。既存の一括回答だけで全製品を完了にしません。
- 個人用のiPhone／Androidで両方のメイン端末を使えるQRの4方向を接続しました。確認済みの現行環境（iOS 18以降／Android 11以降と最新LINE）に限定します。旧版の利用可否と、このレシピの対応を分けます。
- 既存の実際のAccount、旧端末のアプリ・プロフィール、同名の別Accountを区別します。登録したメールはアドレスを入力せず既存Accountを選び、またはメタデータだけを追加します。メール・パスワードを旧端末外で利用できる確認を残し、完全な復旧試験やMFA成功にはしません。
- 直近14日分、同じOSの以前の文章、以前のメディアも必要、アカウント利用だけ、を分けます。標準バックアップの実保存先・iCloud Drive／Googleアカウント・必要なPIN・正常終了、または既に設定済みのPremiumの初回終了・必要な範囲を確認してから切り替えます。初回有料契約は開始しません。
- 「履歴の保管・復元は確認しない」は履歴が一切移らないという意味ではありません。QRでは直近分が自動移行する場合があります。復元画面の「スキップ」も同様です。選んだ範囲の読取りを確認していない限り、履歴の保存・復元済みとは表示しません。
- 外部の最後のログイン前に`requested`を保存します。再開時は操作を繰り返さず、実際の現在画面を確かめます。復元／Google保存先／PIN／既存パスワード／処理中／ホーム／エラーをその都度答え、一操作ずつ案内します。
- 新端末で対象Accountを開ける確認、必要な履歴の実際の読取り、登録番号変更の有無、旧メインLINEの役割を別に記録します。切替の適用後は旧LINEセッションだけを終了し、物理スマホや他のアプリは残します。新端末で既に同じLINEを使う場合は、旧端末での再ログイン・保存・切替を要求しません。既存の旧アプリ記録との対応も明示して確認します。
- 子ガイドの最後の一操作で記録し、同じ機種変更の次の不足へ戻ります。登録メールの新端末確認が不足すれば先にそこへ進みます。LINEが終わっても別製品や不明項目は未完了であり、消去・譲渡の状態遷移も通しません。
- Security Mapへ本人が確認した端末・アプリ・セッション・保存データ・保存先・登録メールの関係を反映します。登録メールはパスワード再設定の連絡先で、全喪失時に復旧できた意味ではありません。LINEを汎用のメールやクラウドのMFA作業として表示しません。

### 12.2 記録・訂正・互換性

`lineSchemas.ts`と`lineValidation.ts`が実体・相互参照、`lineData.ts`が製品一覧と物理状態、`lineCatalog.ts`が日英の一操作、`lineSources.ts`が出典、`lineEngine.ts`が遷移・前提・AI文、`LineGuide.tsx`が画面を担当します。主ガイドと親の`deviceWorkflows`を保持します。

- 製品一覧・子作業・実際の旧新端末・OSの組み合わせ、Account、アプリ、現在セッション、データ、保存先、安定ステップIDを保持します。表示文・出典だけの変更で全完了を消しません。
- 確認ごとに前提の記録IDを持ち、訂正した確認とそれに依存する結果だけを撤回します。登録メールの訂正で正常終了した無関係なトークバックアップを消さず、同じメールを再確認してもAccountを重複作成しません。
- 実際の切替の適用・旧セッションの終了は確認の取り消しでも残します。切替後にデータ範囲を訂正する場合は現在読める対象を確かめ、古い端末の復活や新しいバックアップ実施を推測しません。
- 新端末を別物へ変更したり、同じ端末レコードのOSを訂正した場合は、過去の作業・結果を残して新しい条件を作ります。購入前の準備は同じ旧端末・OSに限って実際の新端末へ接続します。
- 旧v1・モデル1〜12の未知項目・ID・進行・暗号化封筒を保持します。旧モデルの同名未知ストアは競合として保護します。他のガイドによる保存もrevision13とこの履歴を保ちます。将来の未対応モデルの退避試験は14で行います。

既に新端末を使っていた人の`appliedAt`は、このアプリが現在の切替結果を観測した日時です。過去の実際の引き継ぎ日時を推測した値ではなく、電話番号等の24時間制限の自動カウントダウンには使いません。制限の解除は正規のLINEの現在表示で確認する専用経路として追加します。

### 12.3 継続する実装と試験の境界

登録メールの新設・変更、既存LINEパスワードの失念からの準備、パスキー方式、番号・連携方式、旧端末なし、Quick Startの専用本人確認、メーカー別、Premiumの新規導入、変更後の番号更新、旧Androidをサブとして設定する操作は未完了です。安全な既存方式を変更させず、未完了の分岐へ進めます。特に、既存パスキーだけで十分な人へ不要なパスワード変更を強制する代用はしませんが、現在の初期レシピは登録メール・保存済みパスワードを確保した経路に限ります。

アプリ内状態遷移の単体32件と画面5件を追加しました。単体には4方向、既存新端末、暗号化再開、未確定切替、別製品の消去ガード、同名Account、依存だけの訂正、OS訂正、旧1〜12を含みます。画面は日英・390px・キーボード・再読込み・元の機種変更とMapへの復帰・復元中・例外の手動相談を検証します。全体回帰と配布の最終結果は[実装状況](IMPLEMENTATION-STATUS.md)で記録します。これらは実際のLINEアカウント・実機移行・消去の自動試験ではなく、LM01〜40全体の合格宣言でもありません。
