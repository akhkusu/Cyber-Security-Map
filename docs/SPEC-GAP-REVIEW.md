# 仕様の不足点レビューと追加要件

更新日: 2026-11-13

対象は[全体仕様](PRODUCT-SPEC.md)と[パスワード管理・認証アプリ補完仕様](PASSWORDS-AUTHENTICATORS-SPEC.md)です。利用者からの指摘を受け、製品候補の不足に加え、「その製品で利用・復旧まで進められる仕様か」を点検しました。

このレビューによって仕様に追加したことと、アプリへの実装完了は別です。特に、現行アプリで個別経路があるマネージャーはBitwarden・1Passwordです。追加候補や認証アプリ専用の全経路が既に使えるという意味ではありません。実装状況は[別表](IMPLEMENTATION-STATUS.md)で管理します。

## 1. 重要度の意味

- **必須**: 未対応なら、該当経路を公開する前に解決する。秘密の喪失・誤った完了・誤案内に関係する。
- **対象拡張**: 完全な製品目標に含む。確認済み経路から段階的に追加し、初期実装だけで完了としない。
- **保守要件**: 新規レシピ・仕様変更のたびに継続して適用する。

件数の多さだけで優先度を決めません。利用者が選んだ経路でのロックアウト防止、正しい保存、実ログイン、独立した復旧を優先します。

## 4. 次の実装へ渡す作業単位

1. **既存経路の不足を補う**: Bitwarden・1Passwordの利用中点検、認証アプリ選択、別の解除情報、不要な変更の省略、復元テストの条件。
2. **組込み機能**: Apple・Googleを独立した正式経路にする。既存Apple／Google Accountの記録を再利用し、MFAを重複させない。
3. **NordPass・Proton Pass**: 基盤ログインと保管庫解除、二種類の復旧、実ログインまでを各製品の単位で実装する。
4. **認証アプリ**: 製品・OS別の追加操作、同期、バックアップ、旧端末あり／なし、OS間移行を段階的に実装する。
5. **依存モデル**: 保存・同期・解除・復元の関係を追加し、本人が確認した循環と独立した予備の有無を表示する。
6. **残る候補**: ローカルDB、ブラウザー、メーカー、企業向け、サービス専用の順も利用者の必要性に合わせて見直す。

各作業単位は、日英の具体的操作、例外、復旧、根拠、既存データの維持、経路テストまでを含めます。候補を選べるボタンだけ追加して対応済みにする実装は、この仕様を満たしません。
