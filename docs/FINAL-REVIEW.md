# 標準マネージャーの最終レビュー

レビュー日: 2026-11-15。対象: PR #6 の今回の追加実装。これはアプリの状態遷移・表示・保存のレビューであり、外部サービスでの実機ログインや復旧を代行・認証した記録ではありません。

## 日本語と操作性

- 日英の390px幅で、現在のAccount・保管庫・物理端末・アプリ／プロフィールを表示し、横方向のはみ出しがないことを画面試験で確認する。
- OSの選択は内部の略号ではなく、iPhone / iPad・Mac・Android・Windows・Linux等の名称で表示する。
- 一度に必要な質問を一つずつ出す。保管庫を開けた確認、入力方法の確認、実際に保存パスワードが受け付けられた確認を分ける。
- 1Passwordのログイン先の調べ方を先に案内し、地域や組織のホストを推測しない。契約形態とログイン方式は別々に質問する。
- SSOの承認元を選ぶだけでは利用成功を記録しない。承認元の読み出し、IdPのログイン、リンクの承認、新しい場所の保管庫読み出しを分ける。
- 暗号化保存から再開した際、元の質問・Account・対象端末を保持する。保存失敗では元の位置を保持し、同じ回答を再試行できる。
- 機種変更は独立した子作業を持つ。主ガイドの位置・履歴・選択中の保管庫／アプリを保持する。

## 安全性への実効性と修正した境界

| 検出した問題 | 修正・検証 |
| --- | --- |
| Account単位の完了だけでは、別保管庫・別端末の利用まで成功に見える | 保管庫・アプリ・物理端末・プロフィール・提供先・認証変更ごとの観測と保存候補へ接続。組み合わせ変更では古い成功を履歴として残す |
| 同じ接続の古い履歴が再確認後の表示より優先される | 履歴を保持し、現在有効な接続をグラフで優先する。再確認前後の回帰試験を追加 |
| 同じアプリ記録を別端末へ編集すると、以前の成功が移る | 実端末／クライアント／プロフィールの署名を保存し、現物との不一致を無効化 |
| 承認・復旧準備だけでアクセス経路ができる | アクセス経路は実際の読み出し・パスワード実利用からのみ作る。未確認の端末損失時の独立性は不明として扱う |
| マスター変更の受け付けだけで次へ進める | 現在値・新しい候補・控え・製品別Web変更・受け付け・新しい控え／Kit・新しいパスワードの実利用を分離。受け付け後に変更やAccount作成を繰り返さない |
| 古い候補や変更前の成功を流用できる | 生成と受け付けを試行IDへ結び付ける。新生成・ホスト／方式変更・既知の認証リセット後に以前の成功を流用しない |
| 同じ現物アプリを別IDで登録すると、自分自身を承認元にできる | IDのほか、物理端末・クライアント・プロフィールの一致でも承認元から除外 |
| 機種変更の別移行先・別セッションの成功で完了できる | 親作業・Account・実移行先・子セッションに結び付け、以前の移行先は履歴に残す |
| SSO／ベータの一般前提が新端末用手順へ割り込む | 新端末の導入手順と共通の実利用確認を専用前提で制御。方式固有の前提は対応するログイン手順へ適用 |
| 旧形式や未定義項目を通常保存で消す | モデルrevision 15、未知項目の保持、旧IDの保持、将来形式の書き戻し拒否、暗号化往復を試験 |

実際のパスワード・Secret Key・復旧コード・QR・認証コードを入力・送信する欄は追加しない。AI補助は未解決時の手動コピーだけで、メール・組織ホスト・呼び名・プロフィールを含めない。

アプリ外で行った認証情報の変更や権限失効を自動検知する機能はない。既知の変更は確認を失効させるが、記録は本人の実行結果の申告であり、継続監視や安全性の保証ではない。
