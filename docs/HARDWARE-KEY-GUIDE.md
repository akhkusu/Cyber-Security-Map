# 物理キーとパスキーの操作ガイド

仕様確認日: 2026-11-14。全体仕様の追加契約であり、他の製品・紛失・機種変更・削除の要件を置き換えない。

## 対象と役割

通常の基本対策に、物理キーの購入を必須化しない。既に所有するキーを使う人が、対策の途中またはSecurity Mapの実際のアカウントから開始する任意ガイドとする。

| 分岐 | 実施すること | 混同しないこと |
|---|---|---|
| Googleの物理キーによる2段階認証 | 既存または新規のキー登録、別のログインで利用確認 | FIDO2のパスキー登録とは別 |
| Googleのキー内パスキー | FIDO2キーへの登録、実際のパスキーによるログイン | スマホ・ブラウザープロファイルに作るパスキーとは別 |
| Apple Accountのセキュリティキー | 対応するiPhone/iPad/Macから、物理的に別の2本以上を設定・確認 | 通常の6桁コード、Appleの復旧キー、他サービス用パスキーとは別 |
| BitwardenのPasskeyによる2段階ログイン | マスターパスワードに続くFIDO2認証 | ログイン用パスキー、他サービスのパスキー保存とは別 |
| Bitwardenのログイン用パスキー | FIDO2ログインと、実際の暗号化対応状態・保管庫を読む操作 | PRFによる復号は別の能力。ログインだけで復号できたと扱わない |

最初の実装範囲は個人用アカウント、利用者所有の物理キー、Webでの新規ログイン確認。管理ポリシー、自己ホスト、子供用Apple Account、高度な保護機能、端末内・同期型パスキーの新規作成は別レシピの対象と明示する。対応未確認の場合に通常の個人用手順へ流さない。

## 必要になった時に聞く情報

1. 実際のアカウントをそのまま使う。メールアドレスは入力させない。
2. 今回の目的を一つ選ぶ。Bitwardenでは二段階認証とログインを別に選ぶ。
3. 個人用・管理対象などの適用条件。Bitwardenは実際のUS/EUサーバー、Googleは通常か高度な保護か。
4. 実際に操作する端末。既存端末を再利用でき、別端末はOSと呼び名を一つずつ聞く。
5. 実際のキー。既存キーを選べる。新しい物理物は呼び名だけ。シリアル・PIN・認証情報を保存しない。
6. Appleは2本目を選び、別名の同一物ではなく物理的に別であることを確認する。
7. 既存登録の確認か追加か。既存の同一登録を明示的に再利用できる。
8. 実際のブラウザーとプロファイルを特定する。別端末・別プロファイルの利用実績を引き継がない。

選択だけでは設定・復旧・ログインの確認記録を作らない。端末・キー・登録・ブラウザーは別の実体として持つ。

## 共通の安全な順序

- 現在使えるログインを残す。Bitwardenのマスターは端末や保管庫の外から取り出せるようにする。
- 既存の2段階認証があるBitwardenでは、現在の復旧コードを先に保管する。初回有効化では、現在の保管庫を開いたまま、登録直後に復旧コードを保管し、それから新規ログインを試す。
- Googleは別の既存認証方法・復旧用情報を確保してから追加する。新規キーを使うために古い方法を先に削除しない。
- Appleはすべてのサインイン済み端末の対応OS、少なくとも2本、通常の2ファクタ認証、端末の画面ロックを確認する。古い端末・90日以上非アクティブの端末への影響を追加前に示す。
- 登録した表示と、実際にそのキーで認証できた表示を別のステップで確認する。
- 元のログインを残したまま、未ログインの別のブラウザー環境で試す。プライベートモードで非対応なら、本人専用の別プロファイルを使い、共有環境へ資格情報を作らない。
- 既存セッションが開いただけ、別のキー・別の方法で通れただけの場合は、そのキーの利用成功にしない。
- 新しい方法で使えたと確かめるまで、既存の認証方法・端末・キーを削除しない。このガイド内で一括失効、キー全体のリセット、全端末サインアウトは要求しない。

## 画面と操作の粒度

質問、設定画面を開く、登録を始める、OSのキー操作、設定の保存、状態の確認、新しいログインを開く、キーを使う、目的の内容を読めるかの確認を分ける。各操作は場所・押す項目・期待する表示・進む条件・自然なボタン文言を持つ。

公式リンクは設定画面を開くために使う。説明ページを読むことを通常の必須作業にしない。OSダイアログの未確認の文言を創作しない。別の保存先が初期選択されている場合に選び直す方法と、指定の選択肢がない時に止める分岐を付ける。

既に登録済みなら登録操作を繰り返さず、その登録の確認と実際の利用へ進む。Appleは2本をそれぞれ使って確認する。同じ物理キーの別アカウント登録まで完了させない。

## 製品固有の条件

### Google

パスキーの作成はFIDO2が必要。従来の2段階認証の物理キーとは役割を分ける。パスキーによってパスワード入力を省ける設定の説明を折りたたむ。作成済みキーがすぐ使えず待機が必要な場合、登録を残して利用確認を後回しにできる。時間の経過だけで成功にしない。2023年5月以前の登録の変換に削除が必要な場合は通常の追加手順から外し、別の利用可能な方法を先に検証する専用移行が必要。高度な保護とWorkspaceは標準の個人アカウント手順で代用しない。

### Apple

物理的に別のキーを2本以上、最大6本。すべてのサインイン済み端末がiOS/iPadOS 16.3、macOS 13.2以降。Windows用iCloudは15以降。管理対象・子供用Accountなどの制約を扱う。NFCはiPhoneのみ。対応するコネクターと実際の端末を確認する。関連端末の見直しでは、必要な端末のログインを維持する。信頼できる端末とキーをすべて失うと復旧できない可能性を、追加前に説明する。復旧連絡先や一般のAccount復旧をキー喪失時の保証にしない。

### Bitwarden

二段階ログインはSettings → Security → Two-step loginのPasskey、ログイン用パスキーはMaster password内のLog in with passkey。確認する設定画面を分ける。FIDO2登録の上限とログイン用パスキーの上限は別。既存登録を再利用し、上限で古いキーの即削除を促さない。

ログイン用パスキーは二段階認証を迂回する方式で、二段階認証設定の完了と同一視しない。復号対応はブラウザーと認証器のPRF対応、およびその登録の実際の設定による。Used for encryption / Set up encryption / Encryption not supportedを区別し、ログイン後にマスターを要求された場合はマスターで開ける分岐を示す。Bitwarden自身へのログイン用パスキーをBitwardenの保管庫へ保存させない。

## 例外・修正・再開

画面が違う、項目がない、権限・対応条件、キーを読めない、PINが分からない、別の方法が使われた、待機表示をその場で選べる。PINを繰り返し推測させない。キー全体のリセットは他の登録を失うので通常の解決方法にしない。組み込みの分岐で解決できないときだけ、サービス・OS・目的・現在の操作・期待表示・困りごと・公式出典を含むAI相談文をコピーできる。秘密値、呼び名、個人情報、全回答は相談文へ入れない。外部送信しない。

途中保存は暗号化データに含め、同じ質問・操作から復帰する。後回しでも設定済みの実体は消さない。回答の修正と完了記録の取り消しは、実際の設定の削除・キーのリセットではないと示す。登録後に別のキーへ回答だけで付け替えない。別の対象を使う場合は新しい作業にする。完了ボタン一回で記録と次への移動を行う。

## 記録・Map・互換性

物理キーと、アカウント内の各登録を別IDで保持する。Bitwardenの二段階用・ログイン用は、同じキーでも別の登録として扱う。Googleでは、同じパスキーを2つ目の手順にも使える。実際に同じ登録だと利用者が選び、対象の役割で確認した場合は同じIDを再利用し、役割ごとの利用確認を分ける。設定の確認から確認済みの関係を作り、利用の確認から対象・キー・登録・実際の端末/ブラウザーに限定した実績を作る。未確認の独立性や全端末喪失時の利用可能性を推測しない。

利用記録を取り消すと、その記録由来の進捗と利用の根拠を取り下げる。既存の別ガイドの完了は共有台帳で維持する。物理キーの紛失や端末の初期化後、戻しただけで過去の実績を復活させない。説明だけの更新で完了記録を消さない。

任意の拡張ストアを追加し、既存暗号化形式、旧payload、バックアップ、既存ID、主ガイドの進み具合と未知フィールドを保持する。既存の未知フィールドが新ストア名と衝突した場合は、元データを変更せず開始を止める。参照中の項目の削除を拒否し、Mapから元の作業へ戻れるようにする。

## 必須の確認

5方式それぞれ、新規/既存、キー別・アカウント別、設定のみ/実利用、途中再開、戻る、後回し、取り消し、旧データ維持、衝突拒否を検証する。Appleは同一キーの二重選択と物理的同一物の誤登録を防ぐ。BitwardenのPRF非対応でマスター入力へ進み、MFA設定が完了扱いにならないことを確認する。Googleの待機を成功扱いにしない。通常のブラウザーテストは外部サービスへリクエストせず、実アカウントの設定変更はしない。

390pxの日本語/英語、キーボード、設定画面リンクの別タブと戻り先、PagesのプロジェクトURL、Dockerのみのビルド・テストを確認する。実在設定画面の未確認画像は使わず、必要なら明示した操作順の説明図を使う。
