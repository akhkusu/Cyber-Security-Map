# Proton Pass・NordPassの実装契約

資料確認日: 2026-11-13。全体仕様の製品一覧を、そのまま全対応と表示しないための実装・保守契約です。外部サービスの実設定を自動操作・自動検査したという意味ではありません。

## 認証主体・保管庫・端末を分ける

| 製品 | アカウントへのログイン | 保管庫を開く秘密 | 別に確保する復旧情報 |
| --- | --- | --- | --- |
| Proton Pass | 実際のProton Account。Mail・Drive・VPNと同じAccountなら同じID | 通常は同じProtonのパスワード。設定済みの場合のみ追加のPassパスワード | MFA用コード、Proton外の復旧フレーズ、追加のメール／SMS再設定方法、復旧ファイルを区別 |
| NordPass | 実際のNord Account。NordVPN・NordLockerとも共通 | Account用とは別のMaster Password | Accountのメール受信・MFA用10コードと、保管庫用24文字Recovery Codeを区別 |

偽の「マネージャー用Account」は追加しません。個人用の論理的な保存先を `vault`、物理端末・ブラウザープロファイルごとの利用場所を `installation` とします。今回は個人Account全体の保存先を扱い、個々の共有コレクションを作業済みとしません。

本人が同じ実際のAccountを選んだときだけ、メール・クラウド・PassのMFA／復旧を共有します。似た名前、同じ製品、別名アドレスだけでは統合しません。新しい端末・別プロファイルへ、以前の「開けた」「入力できた」の証拠をコピーしません。

基盤Accountを変更するときは、古い利用場所と履歴を残し、新しいAccount側の端末を改めて選びます。仮IDを既存の保管庫へ対応付けるのは、完了記録・参照がない場合だけです。引用符・逆斜線を含む取込み済みIDも、生の文字列とキーで参照を調べます。

## アプリ内の基本順序

1. 製品と、登録済み／別の個人保管庫を選ぶ。
2. 実際の既存Accountを選ぶか、初めて作ることを明示する。仕事・学校の管理用は専用の未完了分岐へ進む。
3. Nord Accountのログイン方法を必要時に質問する。直接のパスワード／メール確認と、Google・Apple接続を区別する。
4. 既存保管庫を維持するか初めて作るかを確認する。
5. 実際に使う端末・プロファイルを選ぶ。PCではブラウザーと区別用の呼び名、iOS等では手順の分岐に必要な世代だけ質問する。
6. 正規アプリ／拡張機能を開く。Accountのログインと、保管庫の解除を別に確認し、本人の個人用保存先を確認する。
7. 製品固有の復旧手段を確保する。基盤AccountのMFA・復旧に不足があれば、その実際のAccountを保護して戻る。メインメールのIDは変更しない。
8. 端末ロックと、自動入力の提供元／拡張機能を確認する。
9. 重要なアカウントを一つ選び、現在の使えるログインを保存する。専用の強いパスワードなら変更を省略する。
10. 正規サービスで保存したパスワードを実際に使う。記録と次への移動を一回のボタンで行う。

各画面に操作する場所・今回の操作・確認できたら進む状態を表示します。出典と資料確認日は折りたたみに置きます。説明を知るための外部ヘルプ閲覧を基本経路にしません。正規の設定・アプリは別タブで開き、このアプリへ戻って続けます。

## 対応環境と分岐

| 環境 | 今回の案内 | 境界 |
| --- | --- | --- |
| Proton Pass iOS / iPadOS | 18以降、17の世代を分岐。Profileから自動入力設定、Login作成・生成・実利用 | ストアが非対応とするOSは未完了。資料から最低対応OSを推測しない |
| Proton Pass Android | Profile → Autofill、Loginの生成・保存・利用 | Androidメーカーの表示差はその場の例外へ。全メーカーの実機照合済みとはしない |
| NordPass iOS / iPadOS | 公式モバイル項目資料の18以降。設定 → 一般 → 自動入力とパスワード | 以前のOS／不明は未完了 |
| NordPass Android | 同資料のAndroid 9以降。Profile → Settings → Autofill → Open Device Settings | 以前のOS／不明は未完了 |
| PCのブラウザー | Chrome / Firefox / Edge / Safari / Brave / Opera、実際のプロファイルに正規拡張を導入 | OS単体・デスクトップアプリだけの導入で自動入力を完了しない。その他のブラウザーは未確認 |
| NordのGoogle / Apple接続 | 接続を残し、Account detailsで確認する案内 | 完全な個人SSO経路は追加対象。接続解除・Account再作成・唯一の認証の移動をしない |

Nordの汎用ダウンロードURLはブラウザーによって転送されるため、確認済みのiOS・Android・各ブラウザーの公式URLに分けます。Braveは公式Chromeページが明示するChromium用拡張を使います。

## 強い語句の準備

初めて保管庫を作る前に、その保管庫内でしか使えない生成機能を要求しません。EFFの7776語の単語表を同梱し、実物のサイコロを5回振る→該当行の単語を私的に控える、を6語以上まで繰り返す方法を案内します。語順を維持し、好みの単語への差し替えや文章への選び直しはしません。

製品が文字種を要求する場合も6語を減らさず、必要な文字種・別に振った数字・許される区切りを補います。Bitwardenの12文字の必須条件と、NordPassの12文字以上等の推奨を区別します。専用の語句は、Account用・Master用・このアプリの保存用で使い回しません。

紙の控えは用途を明記し、端末から離れた他人に読まれない施錠できる場所へ置きます。通常の同期写真に撮ったり、唯一の控えを同じ保管庫の中だけに置いたりしません。単語・出目・パスワードは本アプリへ入力しません。使える信頼できる生成機能も実物のサイコロもなければ、後回しにできます。

- 著者・ライセンス: Joseph Bonneau / EFF、[CC BY 4.0の公式方針](https://www.eff.org/copyright)。配布物にも出典・帰属を同梱。
- SHA-256: `addd35536511597a02fa0a9ff1e5284677b8883b83e986e43f15a3db996b903e`。
- 本アプリが秘密を生成・保存する機能ではない。単語表はPagesプロジェクト配下・オフラインのPWAでも取得できる。

## Protonの復旧

MFAのバックアップコードは、Protonの暗号化済みデータを復号する方法と同じではありません。

- Recovery phrase: Account設定のRecovery → Advanced recovery options。現在の12語またはRecovery Kitが利用可能なら維持する。未設定の場合だけ作成する。Proton Pass／Driveに唯一の控えを置かない。
- 追加のPassword reset options: 設定済みのEmail／SMSを確認するか、Add and verifyから本人確認まで進む。Proton Passだけに依存せず宛先を利用できることを確認する。これ単体でデータ復号ができるとは表示しない。
- Recovery file: Recovery → Data recovery options → Recovery file。既存ファイルを確認するかDownloadで保管する。パスワードと分け、Proton外から取得できる場所へ残す。Void allや、確認目的のパスワードリセットを指示しない。

準備したことだけを記録し、「全端末を失っても復旧できた」「復元試験成功」の観測は作りません。

## NordPassの復旧・既存マスター

24文字の保管庫用Recovery Codeを、NordPassの外へ保管します。現在の有効な控えがあれば再発行を要求しません。新しく作る場合のみ、Reset Recovery Codeが以前のコードを使えなくすることを先に説明し、本人の意図を確認できる条件を示します。AccountのMFA用10コードとは用途も保管対象も別です。

既存マスターが専用で十分に強ければ維持します。弱い・使い回し・確認できない場合は、復旧とAccount保護を先に整え、現在のマスターが使える条件で、次を一つずつ案内します。

1. 現在の利用と独立した復旧情報を残す。
2. 新しい専用の語句を作る。
3. 保管庫の外へ変更候補を控える。
4. モバイルProfile → Settings → Change Master Password、または正規Web保管庫のSettings → Securityを開く。
5. 現在・変更後のマスターをNordPassだけへ入力し、変更する。
6. 新しいマスターで同じ保管庫を解除し、既存の内容を確認する。生体認証だけの解除で済ませない。

再度弱いと回答した別の変更要求は別の作業キーにし、前回の変更完了を流用しません。作成済みのAccount・マスターの初期手順を戻って読んでも、新しい秘密の作成や保管庫の再作成は要求しません。回答を既存利用へ直した場合も、過去のステップID・記録を残します。変更を記録した後で確認を取り消しても、現実のマスターが元へ戻ったとは扱いません。変更以前の利用観測も自動復帰させません。

現在のマスターが不明な場合のRecovery Codeによるリセット、両方を失った場合の損失を伴うリセットは、この通常の変更経路で強行しません。専用の復旧経路は追加対象です。

## サービスのパスワード変更と実利用

生成した候補で、現在使える保存項目を先に上書きしません。使える現在のログインを残す→新規生成→別の一時項目へ保存→サービスの正規設定で変更→受け付け後に元の保存項目を更新→別のログインで実際に使う→不要な一時候補だけを整理、の順序です。

選んだ対象がマネージャー自体の基盤Accountの場合、変更候補を同じAccount／保管庫の外にも先に確保します。変更後のAccount情報で再ログインでき、同じ保管庫が残ることを確認してから保存を仕上げます。Nord Account用の変更では、保管庫用Masterは変更しません。Protonでの通常変更と、暗号化データを失い得るパスワードリセットは混同しません。

現在のセッションを残し、保存したパスワード自体でログインを試します。パスキーだけ、ログイン済みの画面、保存項目の編集だけでは完了にしません。プライベートウインドウで拡張が使えなければ、関係のない権限を追加せず正規マネージャーからコピーできます。

## Security Map・取り消し・相談

- 実際に開いた端末上のアプリ、保管庫、基盤Account、値を持たない保存ログイン／復旧手段を区別する。
- Accountのログインと保管庫の読取りを分ける。通常利用の記録を、新端末・全端末喪失時の復旧成功へ変換しない。通常利用時に全MFA依存先を確認したとは限らないため、別の端末を失う未検証の条件では「利用可能」と推測せず未確認にする。確認済みの必須端末が失われる条件は利用不能として示す。
- 保管庫の状態は、同じ実際の利用場所で準備と現在のパスワード利用が揃ったことを根拠にする。別のプロファイルの断片を寄せ集めない。
- 前提を取り消すと、派生する確認・関係・利用観測も訂正する。参照される履歴を削除しない。
- 復旧手段のノードから現在の控えの確認へ戻れる。以前の新規作成の選択を自動で再実行せず、現在の控えを維持するか、新たに作るかを本人が選ぶ。
- 相談文は、製品・許可されたブラウザー名・OS世代・今回の操作・期待表示・選んだ困りごと・公式出典に限定する。Account名・端末名・プロファイル名・生の回答を含めない。未解決時だけ手動コピーする。

## 保存互換性と機種変更の境界

暗号化封筒のv1形式・KDF・IndexedDB識別子は維持します。既存のデータ本体v1／モデルrevision 1をそのまま読み書きし、この追加機能の初回だけモデルrevision 2へ拡張します。古いrevision 1専用読込みは、新しい意味を解釈して書き換える前に拒否します。新しい説明の配布だけで既存の完了記録を消しません。非対応の将来revisionは書き戻さず、元の暗号化ファイルを退避できます。

今回の機種変更接続は、旧スマホで確認済みのProton Pass／NordPassがある場合に、Accountのログインだけで保管庫まで移行済みにしない消去ガードです。任意の機種変更内で、新しいクラウド保管庫アプリの導入・解除・保存ログインを一貫して確認する経路は追加対象です。主ガイドの位置を書き換えて代用しません。

## 出典・残る実装

操作データと確認日は `src/cloudSources.ts`、通常操作は `cloudManagerCatalog.ts`、復旧は `cloudRecoveryCatalog.ts`、マスター変更は `cloudMasterCatalog.ts`、保存・変更・実利用は `cloudPasswordCatalog.ts`、Nord AccountのMFAは `nordAccountCatalog.ts` で管理します。語句の作り方は `passphraseCatalog.ts` を共用します。

追加対象には、Nord個人SSO、Protonの任意の追加パスワードの導入・変更・専用復旧、共有・組織用、全旧OS、全パスキー方式、製品間インポート／移行、失った現在のマスターからの復旧、機種変更の完全な専用経路があります。Norton・KeePass系等の別製品を今回の対応と表示しません。全実機での画面照合・第三者の設定画面画像も未完了です。

検証の件数と対象は[実装状況](IMPLEMENTATION-STATUS.md)へ記録します。公式資料の確認、アプリ内経路テスト、外部の実機・テストAccountでの操作は別の証拠です。
