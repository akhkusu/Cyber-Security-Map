# Security Mapの登録・訂正・非表示

資料・仕様確認日: 2026-11-14。到達仕様は[全体仕様](PRODUCT-SPEC.md)と[主要系統・モデルの監査](MAJOR-PLATFORMS-MODEL-AUDIT.md)を参照する。この契約はMapの記録機能であり、表にある全製品・全方式の設定手順を実装済みとするものではない。

## 入口と主ガイド

Security Mapの「端末・手段などを追加する」から、必要な項目だけを追加できる。主ガイドの必須登録を増やさない。主ガイドの全回答・履歴・位置・作業記録は保持し、登録の入力・つながりの入力に別の途中位置を持つ。

最初に種類を選び、同じ実物・本人情報を登録済みかを確認する。既存項目を選んだ場合はそのIDを利用し、同名という理由で統合しない。別のAccount、物理キー、アプリのプロフィールは別IDとする。途中で参照先を先に追加する場合も、元の入力を残せる。

一画面の質問に答えるたび暗号化して保存し、次の質問へ進む。戻る、Mapへ戻って後から再開、入力だけの取り消しに対応する。保存に失敗した場合は画面を進めない。入力中は実体を作らず、最後の確認一回で登録とMapへの移動を行う。

## 登録する項目

| 種類 | 記録すること | 混同しないこと |
| --- | --- | --- |
| Account | 実際の提供元、個人・仕事用、同じAccountで使うメール・クラウド・管理 | サービス名・呼び名が同じでも別の本人情報は別 |
| 端末・機器 | スマホ・PC・タブレット・ルーター・NAS・外付けドライブ等の種類、OS | 機器を追加しただけで設定・バックアップを完了にしない。NAS等をスマホの買い替えへ混ぜない |
| バックアップ・紙 | 紙、暗号化コピー、クラウド、オフライン等の種類 | コピーの登録、内容の読取り、復元成功、独立性を分ける |
| ネットワーク | 自宅・職場等のネットワークの区別 | ルーター本体、回線、ネットワーク設定は別 |
| 電子ID | 見分ける呼び名 | 実際のID番号・本人確認情報を入力しない |
| 人 | 自分、復旧協力者、管理者等の役割 | 名前や連絡先は求めず、協力の依頼・承諾・利用準備とは別 |
| 組織 | 所属・管理する組織の呼び名 | 組織の登録で管理権限や復旧能力を確定しない |
| 端末上のアプリ | 製品、実際の端末、必要なプロフィール、版、保管庫、認証コードの保存・同期先 | 同じ製品の別端末・別プロフィールを一括完了にしない。認証アプリ以外にコード保存の質問を強制しない |
| 保管庫 | 製品、Account／ローカル、基盤Accountか実際の保存端末、所有者 | 保管庫と、その保管庫を開く各アプリを分ける。製品の選択を導入済みにしない |
| 認証・復旧手段 | パスワード、TOTP、パスキー、物理キーの登録、アプリ用秘密、復旧コード・キー、API・SSH・証明書等の種類と役割、対象、保存先 | 実際の値は記録しない。物理キー本体と、各サービスへの登録を別にする |
| 識別子 | メール別名・電話番号・ドメイン・ログインID等の種類と用途、対象 | 識別子の値は入力せず、認証の秘密・Account・回線と分ける |
| 電話回線 | 実際の端末、通信会社の管理Account、物理SIM／eSIM／不明 | 電話番号、SIM番号、EID、IMEI等を入力しない。回線を登録してもSMSを受信できたとはしない |
| 物理キー | キー本体、確認した接続方法 | 同じキーの複数Accountへの登録を独立したキーと数えない |
| 保存データ | メール・ファイル・写真・メッセージ・保管庫・端末バックアップ等の種類と所有者 | データ本体、保存先、バックアップの場所、読取り・復元を分ける |
| アクセス権限 | SSO・OAuth・委任・共有・所属等の種類、許可側・受取側・対象・許可操作・表示された期限 | 許可を登録してもログイン・閲覧・復旧の成功にはしない。外部の権限を自動で変更しない |
| 復旧協力・緊急アクセス | 対象、協力者、方式、招待・承諾・追加確認・待機・準備済み・取り消しの段階、表示された利用開始日時 | 招待や承諾だけで利用可能にしない。待機日時の経過だけでも成功にしない |
| ログイン中の状態 | 実際のAccount、アプリ・プロフィール、端末、表示された期限 | アプリの導入、長期の認証手段、セッション、同じ端末の別セッションを分ける |

OS・版や日時が不明な場合は、不明のまま残す。日時の入力・表示はUTCと明示する。アプリの製品選択は、登録を分類するための候補であり、その製品の全設定レシピへの対応表示ではない。

同じ秘密のコピーは、種類と対象が同じ既存の手段を本人が明示して選んだ場合だけ、同じコピーグループにする。名前や保存先が同じだからという理由で結合しない。物理キーの別の登録には、コピーグループの質問を出さない。異なる秘密・Accountの手段を共通の復旧方法と推測しない。

## つながりの確認

対象・保存先・利用端末・許可の相手などを選んだ後、関係ごとに一つずつ確認する。すでに実際の設定で確認できた関係だけ「この関係を確認しました」で記録する。不明なら「まだ確認できていません」を選べる。参照先を選んだだけで確認済みにはしない。

確認済みの関係だけを線として描き、未確認の参照は詳細へ残す。未確認の参照を、設定作業や実ログインの完了へ変換しない。既存項目間の任意の関係も、元→相手→関係→確認状態→記録の順に入力できる。逆向きの関係を同じ意味として扱わない。

対象のログイン、追加認証、復号、端末の解除、復元は役割ごとに区別する。記録機能は、利用観測・AccessFact・AccessRoute・主ガイドの完了記録を自動生成しない。独立した予備の手段があることも、単に別の保存先を選んだだけでは確定しない。

手動で追加した関係は、確認、参照先の訂正、確認の取り消しができる。確認を取り消しても履歴を削除せず、外部の設定は操作しない。ガイドが管理する関係は、そのガイド側で確認・訂正し、手動の編集で進行条件を置き換えない。

## 訂正と元データの保持

呼び名の変更だけでは利用観測を失効させない。手動で登録した、ガイド等でまだ使っていない項目は、種類内の既知の属性・参照を訂正できる。参照先を明示的に空へ戻した場合は古い参照を保持したままにしない。保存方式の変更で不適切になった同期先・ローカル端末等も整理する。

端末・対象・保存先などの実際の参照を変えた場合は、その項目を前提にした古い利用観測をそのまま再利用しない。元の観測・未知項目は履歴として保持する。ラベルの変更と、参照先の変更を同じ扱いにしない。

既存のガイドが管理するAccount・アプリ・保管庫、または作業で利用中の手動登録の本人情報・参照先は、単なるMap編集で別の物へ置き換えない。Mapでは呼び名を変更し、設定・利用環境の変更は関連するガイドで進める。別の実物が増えた場合は別登録にする。

入力を始めた後に元の項目が更新されている場合は、古い入力で上書きしない。新しい記録を保持して知らせ、入力を取り消して新しく開き直せる。未定義の旧項目や他機能の付随情報を削除しない。

## 状態の記録と非表示

「利用中」「予備」「利用できない」「紛失」「手放した」「今後使わない」「実際に失効させた」「実際に削除・消去した」「未確認」を別の状態として記録する。実際の状態として確認したことを明示してから保存する。予備という用途だけでは、独立したログイン・復旧の利用試験にしない。

状態の記録は、サービスのアカウント削除・セッションのログアウト・権限取り消し・端末の初期化を実行しない。実際の作業は正規の設定で本人が行い、Mapはその事実と影響を記録する。紛失保護の解除・全体リセットを代用として案内しない。

紛失・失効等の後に状態を訂正しても、以前の利用観測を自動復活させない。新しい実利用を確認するまでは、その観測を再確認が必要なものとして扱う。機種変更の該当する端末・アプリの確認も、古い控えの履歴を削除せずに再確認できる。別の項目の確認や主ガイドを一括で消さない。

現在利用できないと記録した物理端末・アプリや、実際のオンライン認証で必要なAccountには、新しい完了の記録を作らず、Mapから状態を確認できるようにする。一方、クラウド保管庫やコード同期という分類だけを理由に、既存の端末内の読取り・コード利用へオンラインAccountを必要条件として追加しない。観測した文脈と実際の要求を区別する。

「図から隠す」は表示の整理であり、削除・失効・完了ではない。実体・参照・履歴を保持し、使えない場合の影響確認にも含める。非表示の項目を一覧から選び、図へ戻せる。参照を壊す項目の直接削除を促さない。

## 影響の図

使えない項目は端末だけでなく、キー・回線・保管庫・協力者等も選べる。本人が確認した関係だけから、影響の確認が必要な項目をたどる。所有関係だけでログイン不可とはしない。未知の関係は使わず、循環は訪問済みの集合で止める。

- アプリ→端末、秘密→保存先、保管庫→同期先、復元対象→復元元は、右側を失う場合に左側への影響を確認する。
- 認証手段→Account、復旧手段→復旧対象、セッション→Account、権限→対象等は、手段側を失う場合に対象への影響を確認する。
- 図の強調は影響の確認が必要という意味で、別の利用可能な方法まで失ったという断定ではない。実際に使った経路の評価は、観測・ALL / ANY条件・文脈・未確認の依存から別に表示する。

期限付きのセッション・権限を前提とする利用条件では、記録した期限を過ぎた状態を利用可能にしない。復旧協力の招待・承諾・待機を、設定上準備済みの状態や実際の復旧成功と混同しない。待機・期限の判定を、新しい実認証の証拠にしない。

## 保存形式・UI・更新

機能を利用するときにモデルrevision 6へ拡張する。`securityModel.mapRecordsV1`へ入力・手動登録のID・非表示のIDを版付きで保存する。従来のAccount・Device等のID、payload v1 / v2、暗号化封筒v1、DB・KDF、既存の進行・バックアップを維持する。Nordの接続・復旧等を後から利用しても版を下げない。

旧revisionの同名の不明項目は解釈・上書きせず、競合時は原本を保持する。将来の非対応形式は書き戻さない。既存データの日時の表現やIDを、表示のために書き換えない。IDにURLの区切り文字があってもリンクではエンコードして同じ項目へ戻る。

`mapRecordSchemas.ts`に保存構造、`mapRecordCatalog.ts`に質問・選択肢・関係の説明、`mapRecords.ts`に状態遷移、`MapRecordGuide.tsx`に画面を分離する。`recordAvailability.ts`は明示された利用不能と、確認の時点の範囲を扱う。レシピの説明更新だけで履歴を消さない。

日本語・英語、キーボード、390pxで操作する。機器・アプリ・物理キー・人・回線・権限等に合うアイコンと、色だけに依存しない状態ラベルを使う。グラフ自体は横にスクロールでき、主ガイドは図を理解しなくても進められる。

## 一次資料の確認

- [Google: アカウントにアクセスしたデバイス](https://support.google.com/accounts/answer/3067630?hl=ja) — 同じ端末にも複数のセッションがあり、表示時刻は本人の操作だけを示さないことを確認。端末とセッションを分ける根拠。
- [Apple: Accountのデバイス一覧](https://support.apple.com/ja-jp/102649) — Accountのデバイスとの関連、信頼された利用、削除の影響を確認。単なるローカルのアプリ一覧と同一視しない。
- [Bitwarden: Security FAQs](https://bitwarden.com/help/security-faqs/) — ログイン・ロック解除・複数の利用環境・登録と復旧の区別を再確認。
- [NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html) — 認証手段、認証済みのセッション、再認証等を別の状態として扱う一次資料。Mapが保証する認証強度の数値へ置き換えない。

これらは概念と製品差の根拠であり、全設定操作を照合済みという意味ではない。新しい第三者設定画面の未確認画像は追加しない。QA画像は架空データを使った自アプリの画面とする。

## 残る範囲

独立した復旧や共通障害を収集する全質問、実利用・復旧試験からALL / ANYの条件を作る全UI、共通障害グループ、全製品・全セッション方式の設定・失効手順、機種変更の全シナリオ・全実機照合は追加対象である。手動で項目を記録できることを、それぞれの製品を実際に使える状態まで案内したことにしない。全196条件の完了を示すものではない。


物理キーの手動登録とは別に、[設定と実利用のガイド](HARDWARE-KEY-GUIDE.md)を追加しました。Account・実物のキー・登録・端末／ブラウザーを同じ実体へ結び付け、選択と設定の確認と実利用を分けて表示します。この経路を使うとrevision 7へ拡張します。以後のMap登録でも7を保持し、Mapストアそのもののversion 1とrevision 6由来の記録は維持します。
