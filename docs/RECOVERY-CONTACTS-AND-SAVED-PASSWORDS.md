# 復旧先の確認・保存パスワードの利用・別のログイン画面

更新日: 2026-11-14。追補UX12〜15の実行可能な手順を定義します。この追補に記載した対象経路を実装しています。全製品・全シナリオの対応とは区別し、残る範囲は末尾に記載します。公開結果は[実装状況](IMPLEMENTATION-STATUS.md)とPRの検証欄に記録します。

## 復旧準備を操作へ分ける

「復旧手段を確保」「ログインを維持」だけで準備を済ませません。連絡先の設定を開く操作、表示の確認、その連絡先を実際に開く操作、未登録の場合の入力・受信・公式画面での確認を分けます。現在のアカウント画面は残し、唯一使える認証を先に削除しません。

### Google

1. 「セキュリティとログイン」の「Google にログインする方法」から、再設定用メールか再設定用電話番号を選ぶ。
2. メールを選んだ場合は、「再設定用のメールアドレス」を開く。登録済みのものを使うか、未登録か、利用できないかをその表示で答える。
3. 登録済みなら、同じアドレスのメールを開き、受信内容を読めるか確認する。不要な変更を要求しない。
4. 未登録なら、ログイン用とは異なる普段使うメールを先に開き、その後にGoogleの設定へ入力する。コードを求められた場合だけ受信・公式欄への入力を別の操作にする。
5. Googleが登録を受け付け、正しいメールが表示されることを確認する。このアプリの区別用アドレス欄への入力を、Google側の登録成功に読み替えない。
6. 電話なら、登録番号の確認と今受信できることの確認を行う。未登録・変更の場合は、追加／編集、番号入力、求められた確認メッセージの受信、Google側の確認を分ける。
7. Google Voiceを再設定用番号にしない。番号の追加・変更の反映には最長7日かかる場合がある。実際に待機中の表示がある場合は未完了で残す。

どの復旧オプションも使えない人には、別の連絡先の確認、後回し、すでに有効な認証を変更せず状態だけ見る分岐を用意します。新しい認証方式の導入を、利用不能な連絡先の解決より先に強制しません。

### Microsoftの個人用アカウント

1. 「サインイン方法を管理（Manage how I sign in）」で、登録済みの確認方法を見る。
2. メールが登録済みなら、同じメールを開いて受信内容を読めることを確認する。別名として追加した同じMicrosoftアカウントのアドレスを、独立した確認先に数えない。
3. 未登録なら、先に使える別のメールを開く。「Add a new way to sign in or verify」からメールを選び、入力、受信、コードの入力とNext、登録結果を別の操作にする。
4. 新しいSMSの追加が表示されない場合を扱う。表示されない番号追加を必須にしない。
5. 登録済みの認証アプリ・電話を使う場合は、使える現在の画面を残し、別の未ログイン画面でMicrosoftがその確認を受け付けたか確認する。

個人用に確認方法3件を必須とする条件は設けません。MFAを有効にする前の連絡先の確認と、スマホ紛失時に使う独立した予備は別です。後者では、メインのスマホを使わずに別端末で復旧用メールを開くか、別端末にある登録済みの本人確認を実際に使います。スマホが必要だった場合は未完了です。成功を答えた一回の操作で、復旧の記録と次の必要な質問への移動を行います。

### 確認したメールのつながり

受信・登録を確認した後だけ、既存のメール一覧から公式設定と同じメールを選びます。同じ提供者・似た名前という推測では接続しません。自己参照やメールではない項目は受け付けず、見分けられない場合は関係を追加せず先へ進めます。別のメールへ切り替えても、この選択の途中位置へ戻れます。

このつながりは「このメールが復旧先として登録されている」という確認です。登録だけで完全なアカウント復旧・MFA・スマホなしの利用を完了にしません。

## Bitwarden・1Passwordの保存済みログイン

既存の項目を探すことから始めます。見つかった項目はユーザー名・公式サイトを確認して使い、ない場合だけ新規作成します。既存項目を探しただけで、パスワードの強さ・サービスでの利用を完了しません。

### 今のパスワードを使う

このアカウント専用にランダム生成した十分に強いもので、漏えいしていなければ、そのまま保存項目を使ってログインを試せます。使い回し・弱い・漏えいしたもの、不明なものは新しい候補へ進めます。ボタンは「今のパスワードを使う」「新しく生成して変更する」とし、固有性等の条件は本文で判断できるようにします。

### 変更する

1. 現在使える元のログイン項目を保存する。
2. 正規サービスのパスワード変更画面を開く。
3. 元の項目を残したまま、別の一時的なLogin項目で変更候補を生成する。このガイドの方針は、サービスが許す場合にランダムな20文字以上。製品やサービスの最低条件・制限と、アプリの方針を混同しない。
4. 候補を「変更する前の候補」と分かる項目へ保存し、マネージャーを開き直して取り出せることを確認する。保存済みなら重ねて作らない。
5. サービスの公式画面で変更を確定する。受け付け済みなら、変更を繰り返さず結果から再開する。
6. 受け付けられた候補で元のログイン項目を更新する。拒否された場合は元の使える情報を残す。
7. 別の未ログイン画面で、保存したパスワードを実際に使う。
8. 成功後に、不要になった一時的な候補だけを整理する。元の項目や恒久的な復旧情報は残す。

Bitwardenのこの経路はWeb保管庫を明示し、選んだUS／EUの公式URLを使います。Webのメニューをモバイルアプリのメニューとして表示しません。1Passwordは、メールの操作端末ではなくマネージャーの操作端末に合ったアプリ用資料を使います。古い記録にその端末がなければ、必要になった時にOSを聞き、既存のMFA・復旧をやり直さず元の手順へ戻します。未対応の管理製品を1Passwordとして案内しません。

候補の確認記録は対象アカウントだけでなく、マネージャーの実体IDとBitwardenのサーバー区分にも結び付けます。別マネージャー・別区分の候補を再利用しません。候補の値そのものは、このアプリにも相談文にも入力・保存しません。

### 保存パスワードの実利用

パスキーだけで入った場合、既存のログインが開いただけの場合、端末を解除しただけの場合は、その保存パスワードの利用成功に数えません。違う方法だったと答えたら未確認の分岐へ進み、必要なら正規のマネージャーから手動コピーして使います。すでに誤って完了した同じ確認を訂正した場合は、その記録だけを撤回し、他の対策の記録は保ちます。

メールの認証がすでに有効だと現在の公式画面で確認できた場合も、その一回の回答で確認を記録し、次の対策へ進みます。「確認済み」を別画面で重ねて押させません。サービスを選んだだけの状態は、この確認とは別です。

成功を一度答えると、その記録を保存して次の必要な操作へ進みます。一時候補がない経路では整理を要求しません。旧`save-current`・`change-open`・`generate`・`apply`・`save-new`・`test`のIDは保持します。完了済みのパスワード対策を説明更新だけで消しません。

## 別のログイン画面を開く補助

必要な操作の中から、任意で「別のログイン画面の開き方」を開けます。OS、ブラウザー、Safariの表示差を必要になった時だけ選び、各メニューを一画面ずつ案内します。途中位置は元の作業と一緒に暗号化保存し、補助の完了をログイン成功にはしません。

| 環境 | ブラウザー操作の対象 |
| --- | --- |
| iPhone / iPad | Safariの現在／旧表示／iPad、Chrome、Firefox、Edge |
| Mac | Safari、Chrome、Firefox、Edge |
| Android | Chrome、Firefox、Edge |
| Windows | Chrome、Firefox、Edge |
| Ubuntu | 確認済みのChrome・Firefoxのブラウザー操作のみ。OSの基本対策対応とは別 |

公式URLは用意した画面へコピーして開きます。通常のリンクでプライベート画面を自動作成できたことにはしません。プライベートタブ同士のログイン共有、最初からアカウントが開く場合、iOS Firefoxで戻るとタブが閉じる設定を扱います。管理制限を解除させたり、唯一使える画面からログアウトさせたりしません。

詳しい操作と資料の照合範囲は[ブラウザーの専用契約](PRIVATE-BROWSER-GUIDE.md)を使います。新しいUIの補助はGuideStepを使う対象へ接続し、他の専用ワークフローに接続できた範囲とは区別します。

## 進捗と保存の契約

進捗は、対象の手順に保存された完了記録を数えます。後回し、未受信、拒否、待機や違うログイン方法を完了にしません。選択前の分岐は、一つの進行経路として残りを見積もり、排他的な全分岐を足し合わせません。戻る・再試行の循環で総数を増やしません。未完了の操作がある間は満了のバーにしません。

画面には完了した手順数を表示し、見積もりを固定の総手順数や安全率と表示しません。ブラウザー操作補助は、元の設定の完了数を増やしません。選んだ認証アプリと違う登録の記録も数えません。

既存の封筒・本体モデルの版を維持し、追加の確認記録・再開位置・未知項目を保持します。公式資料の説明を更新しても、既存の完了やバックアップを失効させません。候補や実際の利用先が変わった時の再確認と、文章更新は区別します。
